# 项目长期指令

## 报告中的公式格式

- 以后出现在各种报告、计划、阶段总结、论文草稿和说明文档中的公式，都必须使用读者可直接阅读的形式。
- 面向读者的 Markdown 文档不得把原始 LaTeX 代码当作最终公式展示；禁止遗留 `$$...$$`、`\(...\)`、`\[...\]`、`\frac`、`\sum`、`\arg\min`、`\mathrm` 等代码式表达。
- 优先使用 Unicode 数学符号、上下标和清晰的单行文本，例如：`M = N − D + 1`、`j* = arg min[j] c(j)`、`CVaR₀.₉(R)`。
- 复杂公式应拆成多行可读表达、分情况列表或“公式 + 变量解释”，不能为了缩短篇幅牺牲可读性。
- 公式首次出现时，应在相邻正文中说明主要变量、单位和物理含义。
- 源代码、配置文件和测试中因语法需要而使用 ASCII 或 LaTeX 字符串不受此限制；本规则适用于所有人类读者导向的报告文档。
