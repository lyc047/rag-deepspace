## 3. 冻结的数据适配

Pilot 检查后冻结以下规则：

- 行表示按采集顺序排列的时间场景；
- 列表示频率采样点；
- 数值使用数据集原生 dB 标度 PSD；
- 不做结果驱动归一化；
- 沿频率轴划分为 N 个确定性的等宽连续分组，在原生 dB 标度上取算术平均；
- N 取 8、16、32、64；
- 保留所选 FM 数组的全部行和原始顺序；
- 非有限值不插补，站点直接记为无效；
- 数组没有逐行时间戳，故将各行均匀映射到数据说明所述的 6 小时采集窗口。

最后一项属于数据适配假设。它不会改变任务动作的频谱代价，但会影响“最大状态年龄”触发，因此必须作为外部有效性边界保留。

## 4. 冻结算法与比较

每个场景包含三个连续频谱块需求：D₁ = 0.25N、D₂ = 0.50N、D₃ = 0.75N。任务容差固定为 ε = 0.2 dB，码本上限固定为 K = 4。

系统先用最多 16 个时间前缀场景判断：

1. 是否可以复用四个 AERPAW 开发活动中的预装码本；
2. 是否属于稳定 OOD，并仅利用校准前缀拟合 K = 4 码本；
3. 是否无法稳定解析，并对余下会话退回精确动作。

所有紧凑码字在发送前继续经过精确 regret 校验，不满足 ε 的场景使用 escape 加精确动作。已知 BANK 使用 64 bit 版本化激活帧，最多尝试两次，然后强制完整安装；OOD 使用完整安装。

比较基线为逐场景自包含的精确多查询动作包。两种方法使用相同随机链路轨迹，所有前向、ACK、心跳、安装、恢复、重复和 escape bit 均计入总开销。

bit 节省率为：

`Savings = 100 × (B_exact − B_semantic) ÷ B_exact`

其中 B_exact 和 B_semantic 分别为精确基线与语义系统的总 bit/景。

## 5. 统计方法与门槛

- 每个 N 使用 60 条配对链路轨迹；
- 站点是外部泛化的独立聚类单位；
- 使用 5,000 次“先重采样站点、再重采样配对轨迹”的层级 bootstrap；
- 同时报告按场景数加权结果和站点等权宏平均；
- 置信水平为 95%；
- 24 个站点全部保留，失败或不利站点不得替换。

预注册主门槛要求：

1. 至少 20 个有效站点；
2. 四种 N 的语义场景加权 clean rate 95% 下界均不低于 90%；
3. 四种 N 的场景加权 bit 节省率 95% 下界均大于 0；
4. 至少三种 N 的等站点宏平均 bit 节省率 95% 下界大于 0；
5. 错误码本动作执行次数为 0；
6. 所有 bit 账本恒等式成立。

## 7. 失败定位

直接证据包括：

- N = 16 和 N = 32 的 clean 门槛失败；
- 两者的场景加权 availability 分别为 90.60% 和 91.28%，只比 clean 高约 0.98 和 0.94 个百分点；
- 多个低 clean 站点的 future compact coverage 接近 100%，且 availability 与 clean 几乎相等；
- 错误码本动作执行次数始终为 0。

因此，主要问题不是“码字表示了错误动作”，而是接收端在部分场景中没有可执行动作，即可靠上下文恢复不够及时。

冻结工作点中，N = 8 和 N = 64 的静默心跳间隔为 10 景，N = 16 和 N = 32 为 16 景。ElectroSense 的若干站点频谱动作非常稳定，事件触发更新较少。接收端发生上下文重置后，系统不能依靠新的任务更新迅速恢复，只能等待较长的静默心跳，因而形成连续不可用场景。

“高码本覆盖、低 bit、availability 下降”的联合模式与这一机制一致。该解释是由 Final 输出和状态机规则支持的诊断性推断，不是新的随机对照因果证明。不能在这 24 个站点上调短心跳后重新宣称 Final 通过。

## 9. 扬长避短的下一步

下一阶段只验证一个假设：

> 在动作长期不变化的站点中，缩短或风险化静默探测能否恢复 clean ≥ 90%，同时保留显著的总 bit 优势。

开发数据只能使用 4 个 ElectroSense Pilot 站点、既有 AERPAW 开发活动、已消费数据的诊断汇总和可控的上下文重置仿真。

具体顺序为：

1. 冻结并保留本次 `FAILED` 结果，不覆盖；
2. 在开发集比较 N = 16/32 的 16、10、8、6 景固定心跳；
3. 增加“长时间无任务更新时提高探测优先级”的静默看门狗；
4. 保留硬 regret、码本身份校验、escape 和 fail-closed；
5. 以相同 clean 门槛下总 bit 是否下降作为保留标准；
6. 做按站点留一和长稳定段压力测试；
7. 只有 Pilot 与 AERPAW 门槛共同通过后才冻结新候选；
8. 新候选只在 6 个确认锁箱站点上执行一次支持性确认；若样本量不足，应另找独立数据。

本次失败首先指向可靠性协议，而不是码本学习能力。因此暂不优先加入复杂 AI 排序器、GNN 或强化学习。若固定或风险感知心跳仍不能改善 rate–risk 前沿，再考虑用轻量风险预测器估计“接收端状态失效而任务更新又长期不触发”的风险。
