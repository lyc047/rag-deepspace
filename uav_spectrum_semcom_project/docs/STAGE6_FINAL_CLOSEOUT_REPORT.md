## 1. 阶段目标与最终判定

阶段6研究的问题是：在无需恢复完整频谱状态的前提下，能否利用“多个频谱状态对应同一可接受资源动作”的任务等价关系，压缩资源选择信令，并在丢包、ACK丢失和接收端上下文重置时安全运行。

任务可接受集合定义为：

`Aε(x) = {a：所有业务查询下的最大 regret 不超过 ε}`

本阶段固定 `ε = 0.2 dB`。只要接收端动作属于 `Aε(x)`，系统就不要求恢复完整频谱，也不要求始终执行唯一的精确最优动作。

阶段6的最终判定是：

> 任务等价语义表示的通信开销收益和安全性获得了外部支持；单一固定心跳的跨站点可靠性只获得部分支持，严格的全 N 外部验收失败。

因此，本阶段不是“算法完全失败”，也不能写成“系统总体外部验证成功”。正确表述是：阶段6确认了任务语义压缩的可行性与安全边界，同时暴露了固定周期上下文维护不能适应异质频谱动态的问题。

## 2. 已完成的核心方法

### 2.1 基于 regret 的任务等价表示

系统不上传逐信道功率，而是计算不同连续频谱块在多个业务需求下的任务代价。若多个频谱状态允许使用同一个低 regret 动作元组，则共享同一离散码字。

该机制把通信目标从“恢复信号或频谱状态”改为“维持可接受任务动作”，是本阶段的核心理论主线。

### 2.2 多查询解析码本与精确回退

一个码字同时携带多个候选需求下的频谱块动作。发送端在每个场景使用真实观测计算该码字的最大 regret：

`rₖ = max[q] R(x, Dq, aₖ,q)`

若 `rₖ ≤ ε`，发送紧凑码字；否则发送 `escape + 精确动作`。该设计保证码本压缩不会绕过任务约束。

### 2.3 有状态事件触发语义信令

系统只有在当前接收端缓存动作即将失效、上下文需要恢复或协议状态变化时才更新，而不是逐景发送。协议实现包括：

- 码本身份、版本与哈希检查；
- 接收端动作缓存复用；
- ACK信念集合；
- 激活、恢复与延迟包处理；
- 固定静默心跳；
- fail-closed 解码；
- 有限重复保护。

### 2.4 公平的端到端通信计费

评测统计的不只是语义 payload，还包括前向包、ACK、心跳、码本安装、上下文恢复、重复与精确回退。阶段6由此把“码字很短”推进为“完整协议总 bit 是否节省”的系统问题。

## 3. 外部证据汇总

### 3.1 二十四站点主 Final

主 Final 已单次消费并正式判定为 `FAILED`。

| N | clean rate | clean 95%下界 | 总 bit 节省率 | 节省95%下界 | 主要判定 |
|---:|---:|---:|---:|---:|:---|
| 8 | 91.87% | 90.84% | 41.86% | 29.45% | 通过 |
| 16 | 89.62% | 87.92% | 40.49% | 26.02% | clean失败 |
| 32 | 90.34% | 88.52% | 38.90% | 24.48% | clean失败 |
| 64 | 92.37% | 91.25% | 40.62% | 27.17% | 通过 |

四种 N 的 bit 节省区间下界全部大于0，错误码本动作执行次数为0；但 N = 16/32 的 clean 下界未达到90%。

### 3.2 六站点支持性确认锁箱

主 Final 失败后，仅在开发数据上将四种 N 的固定静默心跳统一为10景，形成 `S6R-FH10-v1`。随后六站点确认锁箱被单次消费，结果仍正式判定为 `FAILED`。

| N | clean rate | clean 95%下界 | 总 bit 节省率 | 节省95%下界 | 主要判定 |
|---:|---:|---:|---:|---:|:---|
| 8 | 90.55% | 89.93% | 57.13% | 38.97% | clean失败 |
| 16 | 92.99% | 91.10% | 39.98% | 16.78% | 通过 |
| 32 | 92.76% | 91.18% | 39.12% | 11.17% | 通过 |
| 64 | 92.07% | 89.90% | 47.04% | 21.68% | clean失败 |

该结果独立支持了 N = 16/32 的目标修复，但 N = 8/64 未通过严格下界门槛。四种 N 的等站点宏平均节省下界仍全部为正，错误码本动作执行次数仍为0。

### 3.3 合并解释

两轮外部证据共同支持：

1. 任务等价码本与精确回退没有产生已观测到的错误码本动作；
2. 与冻结精确动作协议相比，四种 N 的端到端总 bit 节省下界在两轮中均为正；
3. clean 失败的 N 会随站点集合改变，说明问题不是某一个 N 的固定缺陷；
4. 固定心跳只能在平均意义上折中，不能根据站点动态、静默时间和上下文风险自适应分配保护。

## 4. 阶段6可以写入论文的贡献

建议把阶段6收敛为三项贡献：

1. 提出基于多查询最大 regret 的任务等价离散频谱表示，使不同频谱状态能够共享可接受动作码字；
2. 设计带版本校验、ACK信念、精确 escape 和 fail-closed 机制的有状态事件触发语义信令协议；
3. 建立同可靠性约束下的完整 bit 计费和外部验证框架，并通过负结果识别固定周期上下文维护的适用边界。

轻量风险排序、Markov预测和重复保护属于阶段6的辅助探索，不应单独表述为主要人工智能创新。其价值在于证明因果历史中存在可预测的任务风险，并为阶段7提供可复用基线。

## 6. 数据与算法冻结规则

1. 二十四个主 Final 站点和六个确认锁箱站点不得重跑并改写阶段6判定。
2. 上述三十个站点以及四个既有 Pilot 站点可在阶段7中重新标记为“已见开发数据”，用于标签、诊断、训练和内部测试，但永久排除于阶段7外部 Final。
3. 三个储备站点保持未读，访问次数维持0；不用于补足阶段6失败，也不单独承担阶段7 Final。
4. `S6R-FH10-v1` 固定为阶段7的强解析基线，不继续扫描更多固定心跳间隔以追求正结果。
5. 任务码本、`ε = 0.2 dB`、精确 escape、身份校验和 fail-closed 在阶段7首轮保持不变。
