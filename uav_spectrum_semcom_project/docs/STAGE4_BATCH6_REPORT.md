# 阶段 4 Batch 6：解析价值评分与离散预算调度

日期：2026-07-16  
状态：已完成；求解器有效，但当前 G1 可观测量退化，解析评分未通过 Gate B  
证据范围：train 拟合、calibration/validation 聚合评价；final holdout 未建立、未访问

## 1. 冻结算法

在查看结果前冻结解析候选分数，由以下部分相乘：

1. 当前融合资源块最优—次优间隔产生的任务歧义；
2. 候选节点在两个关键连续资源块上相对当前融合的局部分歧与块对比变化；
3. sensing SNR、预测置信度、链路成功概率、age 和削顶构成的可解释可靠性；
4. G2/G3 量化分辨率增益；
5. train-only 十箱 PAV 单调表将原始分数校准到反事实 marginal regret value。

实现了允许 G0 的 value/bit 贪心和精确多选择背包。Gate B 限制最多升级一个节点，并在 520、600、750、950 增量 bit 四个冻结预算上比较。

## 2. 关键可观测性审计

四节点 G1 硬预览在 train、calibration 和 validation 上的“所有节点完全相同”比例均为 100%，节点对平均 Hamming 分歧为 0。与此同时，软 occupancy 相对 1-bit 量化值的平均残差约 0.130，95 分位约 0.233—0.235，说明节点差异存在于被 G1 丢弃的软残差中。

因此所有 2400 个 all-G1 train 候选的解析原始分数完全相同且为 0；秩相关不可定义。PAV 正确退化为全局平均值，解析方法无法形成场景相关排序。报告实现同时修复了“恒定分数使用稳定排序会产生伪秩相关 0.299”的统计呈现问题。

## 3. 预算结果

由于候选校准值相同，解析贪心和精确背包在所有预算下都退化为链路成本最低的固定节点 G2，结果与阶段 3 先验完全一致：

- 平均 regret：`0.025368`；
- CVaR0.9：`0.136736`；
- 期望总发送 bit：`2152.49`；
- clean rate：`0.5267`。

在 600 bit 增量预算下，SNR-G3 的 regret 为 `0.024979`、总 bit 为 `2222.50`。解析方法少用约 70.01 bit，但 regret 差 `+0.000389`，95% CI `[-0.002397, 0.003338]`，不能宣称优势。相对阶段 3 先验的所有差均为 0。

预算 oracle 仍显示明显空间：600 bit 时 regret `0.013466`、总 bit `1858.61`；750 bit 时 regret `0.006864`、总 bit `1909.13`。差距来自候选软信息不可见，而非背包求解误差。

## 4. 工程修复

链路 nominal/期望发送 bit 从依赖 PyTorch 的训练模块迁回 `digital_link.py`，解除纯解析调度与训练框架的错误耦合并消除 OpenMP 运行库冲突。相关 19 项测试通过；全项目基线在本批主体完成时为 121 项通过，新增恒分数测试也已通过。

## 5. 决策 D4-006

不调整已冻结解析公式追逐 validation。当前普通 G1 只足以提供融合基线，不能提供节点选择所需的差异化证据；全量 2-bit G1 已在 Batch 5 被证实会增加成本并恶化 Brier。因此下一批不改变 G1 融合值，而是在预览中增加仅供调度使用的稀疏不确定性残差草图，并为本地质量摘要付费。

残差草图必须满足：真实 bitstream/解码测试、只由本地软 occupancy 产生、部署可见、不得直接替换融合 occupancy、所有预览开销进入相同数字链路。若草图仍不能提高反事实排序或形成 bit-regret Pareto 改善，则 C2 停止扩展，论文保留可观测性负结果和精确预算基线。
