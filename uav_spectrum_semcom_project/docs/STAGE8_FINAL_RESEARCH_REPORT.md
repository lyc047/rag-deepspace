# 阶段8研究报告：真实故障代理标定、协议重放与结论

## 摘要

阶段8研究了阶段6—7可靠性协议所依据的故障模型是否接近真实无人机系统。研究采用33次AERPAW AADM物理试飞和39次ALFA原始飞行，在读取信号前按独立飞行冻结开发—确认划分。开发侧表明，LoRa内部丢包下界在飞行间高度异质，固定10%的同质独立丢包模型过于简单；据此冻结飞行层次伯努利模型，并对无心跳、30、20、16、10和6景心跳开展成对协议重放。没有替代间隔同时满足clean损失不超过0.5个百分点和总bit显著降低，因此未形成新候选。一次性确认侧进一步证明飞行间异质性显著，但发现强段内相关，说明开发冻结模型仍缺少短时突发结构。ALFA两侧均未发现飞控启动回退，但其日志不能观测语义接收端进程及缓存，无法标定上下文重置概率。最终保留S6R-FH10-v1作为压力模型下的工程边界，不宣称真实板载最优；下一步必须转向带状态观测的硬件在环或板载实验。

## 1. 研究问题

阶段7得到的核心负结果是：基于预测的心跳或更新策略没有形成稳定正收益，而固定10景心跳只能作为保守工程边界。阶段8进一步回答：

1. 10%任务包丢失是否可代表真实无人机无线会话；
2. 丢包是否能用同质独立模型描述；
3. 公开故障日志能否标定语义接收端上下文重置；
4. 更真实的故障代理是否会改变固定10景心跳的选择。

## 2. 数据与实验治理

| 数据源 | 独立单元 | 开发 | 一次性确认 | 研究角色 |
|---|---:|---:|---:|---|
| AADM物理试飞 | 33次飞行 | 13 | 20 | 无线链路丢包代理 |
| ALFA飞行日志 | 39次原始飞行 | 19 | 20 | 飞控启动和遥测连续性审计 |

数据划分由固定SHA-256排序在信号访问前完成。ALFA的47个processed序列没有被当作47个独立样本，而是映射回39次原始飞行。确认数据只访问一次，访问前已冻结估计器、开发模型、候选门槛和“无候选”的开发结果。

## 3. AADM开发与确认结果

### 3.1 开发侧

13次开发飞行共重构2512个内部帧位置，缺失745帧，总体下界为29.66%，飞行级95%区间为11.95%—47.45%。飞行丢失率范围为0%—78.38%，显示明显会话差异。

开发侧各计数段的一阶失败相关系数绝对值最大为0.084，未超过0.1。因此冻结的开发模型为：

> 每条协议轨迹先等概率抽取一次开发飞行，再把该飞行的丢失率作为该会话内的伯努利丢失概率。

### 3.2 一次性确认侧

20次确认飞行共重构3690个内部帧位置，缺失516帧，总体下界为13.98%，飞行级95%区间为3.23%—27.08%。

确认结果必须拆成三个层次解释：

- 0.10位于确认区间内，因此不能拒绝“平均值可能为10%”；
- 飞行丢失率范围为0%—80%，同质二项模型的过度离散检验统计量为1901.01，Monte Carlo p≈5×10⁻⁵，因此“所有飞行共享同一丢失率”被拒绝；
- 最大段内一阶相关为0.807，超过0.1，开发侧的“飞行内伯努利”假设没有得到确认。

所以最终支持的是：

> 真实链路至少同时包含会话间质量异质性和部分会话内时间相关，单一固定丢失率不足；开发冻结的层次伯努利模型只完成了第一层改进，并非最终真实故障模型。

## 4. 经验故障模型下的协议重放

使用4种信道规模、8个开发频谱会话和每会话60条配对轨迹，对固定10景心跳与替代间隔比较。

| 候选 | 相对clean变化范围 | 相对总bit变化范围 | 结论 |
|---|---:|---:|---|
| 无心跳 | −20.6至−34.2个百分点 | 节省38.1%至49.4% | 可靠性失败 |
| 30景 | −9.1至−9.8个百分点 | 节省28.6%至30.6% | 可靠性失败 |
| 20景 | −4.8至−5.3个百分点 | 节省18.9%至21.9% | 可靠性失败 |
| 16景 | −3.1至−3.5个百分点 | 节省13.8%至15.3% | 可靠性失败 |
| 6景 | +2.25至+2.41个百分点 | 多耗24.5%至26.5% | 开销失败 |

所有方案的错误码本动作执行次数为0。没有候选在任何N上通过完整门槛，因此没有为失败候选继续消耗确认数据，也没有更新算法或协议。

该结果说明固定间隔方案沿着同一条开销—可靠性曲线移动：间隔越长，bit越少但失步暴露越久；间隔越短，clean越高但心跳开销明显增加。固定10景是当前压力模型与冻结门槛下的折中点，不是理论全局最优。

## 5. ALFA上下文重置审计

开发侧16次有processed覆盖的原始飞行提供0.679小时数据，确认侧15次有覆盖的原始飞行提供0.687小时数据。两侧分别获得3802和4197个MAVLink SYSTEM_TIME启动时间样本，均未发现飞控启动时间回退、MAVROS断开或重新连接。

零事件不能直接解释为零风险。确认侧零事件的描述性Poisson 95%上限仍约为每小时4.36次，且ALFA记录的是Pixhawk/MAVLink/ROS状态，不是本系统接收端：

- 不能观测语义进程是否崩溃或被操作系统重启；
- 不能观测码本目录是否持久化；
- 不能观测动作缓存是否丢失；
- 不能观测接收端重启后首次错误动作或恢复时延。

因此，每景2%的上下文重置概率没有被标定，只能保留为压力参数。

## 6. 创新与研究价值

阶段8没有产生新算法，但形成了三项有效研究贡献：

1. 建立了飞行级、单次确认访问的无人机故障代理验证流程，修正了processed片段伪重复风险；
2. 证明固定同质丢包模型不足，并区分“会话间异质性”和“会话内时间相关”两个建模层次；
3. 通过完整协议重放证明固定心跳的bit节省与clean损失存在稳定权衡，排除了继续微调固定间隔这一低价值方向。

负结果的价值在于收缩后续路线：不能再把主要精力放在预测人为随机重置，而应先让接收端上下文变成可观测、可复现的真实系统变量。

## 7. 十一类统计与推理风险审计

| 风险 | 处理结果 |
|---|---|
| 伪重复 | 以完整飞行而非processed片段为独立单位 |
| 开发—确认泄漏 | 信号访问前按哈希冻结 |
| 确认集调参 | 无候选，确认后不改参数 |
| 可选停止/重复确认 | 两个确认角色均单次访问 |
| 选择性报告 | 所有间隔和N均保留 |
| 聚合/Simpson效应 | 不把混合飞行的Markov参数当作平稳信道 |
| 均值掩盖异质性 | 报告飞行范围、聚类区间和过度离散检验 |
| 代理因果过度解释 | 不把LoRa或飞控故障等同语义上下文重置 |
| 未观测事件等同零 | 报告覆盖时长和零事件上限 |
| 指标构念错配 | 明确内部帧缺口只是上行丢失下界 |
| 外部效度过度声称 | 不声称板载部署或算法外部Final完成 |

## 8. 阶段8最终结论

阶段8公开数据研究已完成，结论为“混合证据、无新候选”：

- 确认飞行支持会话间丢失率异质性；
- 确认飞行不支持完整的飞行内独立伯努利假设；
- 不能拒绝总体平均丢失率恰好为10%，但拒绝所有飞行共享固定10%；
- ALFA不能标定语义接收端上下文重置；
- 固定10景保留为工程压力边界；
- S6R-FH10-v1不修改；
- 阶段6 Final失败与阶段7无独立Final的历史结论不变。

## 9. 下一步唯一有效方向

下一阶段不应继续扫描固定心跳或训练更复杂的预测器。应在硬件在环或实际接收端进程中记录：

1. 设备boot ID和进程启动ID；
2. 码本目录的持久化版本；
3. 动作缓存和update epoch；
4. 每个前向包与ACK的发送、接收和丢失；
5. 掉电、进程崩溃、看门狗重启与网络重连；
6. 从失步到fail-closed、重新安装和恢复可用的时延；
7. CPU、内存、功耗和协议bit实测。

只有获得这些观测，才能把上下文重置从人为概率改为可验证的板载故障过程，并判断固定10景是否应由真实事件式恢复机制替代。
