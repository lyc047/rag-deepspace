## 1. 研究问题

阶段9.4检验：把 S9-RCV2-v1 的16 bit恢复会话标签、目录校验、半窗口串号和 fail-closed 机制接入 S9-HBW30-v1 后，能否在阶段9.1原有四类故障条件下保持任务性能，并使新增通信开销与实际恢复帧数量严格一致。

本阶段不修改30景看门狗，不扫描故障率，不改变任务轨迹，不加入预测器，也不读取新的频谱 Final 数据。

## 2. 配对实验

每条轨迹生成一次任务序列和故障序列，同时运行：

1. 阶段9.1旧 HBW30；
2. 阶段9.4标签 HBW30；
3. 阶段9.4零标签影子协议；
4. 阶段9.1 fixed10；
5. 阶段9.1 boot-event。

标签 HBW30 对旧 HBW30 用于评估安全身份同步对任务性能的影响；标签 HBW30 对零标签影子协议用于精确隔离16 bit标签开销。影子协议与标签候选采用完全相同的安全状态机，只将恢复标签计费设为0。次比较沿用阶段9.1门槛，检查标签候选是否仍保留原协议的主要价值。

## 3. 实现约束

- 启动状态或看门狗响应成功到达后，发送端才能获得当前 boot ID；
- boot ID未知时禁止发送可被接收端激活的恢复帧；
- 标签激活帧为80 bit，标签完整安装帧为419 bit；
- 普通更新42 bit和ACK 24 bit保持不变；
- 每个恢复发送尝试只增加16 bit；
- 新会话建立时清空旧队列，包龄不得超过127次更新；
- 所有无法确认身份或目录的情况均 fail-closed。

## 4. 验收门槛

四类故障剖面分别要求：

- 标签 HBW30 相对旧 HBW30 的平均clean下降不超过0.5个百分点；
- 平均availability下降不超过0.5个百分点；
- 错误上下文执行和旧恢复误接收均为0；
- 每条轨迹相对零标签影子协议满足：新增总bit = 16 × 标签恢复发送次数；
- 普通更新bit和ACK bit与零标签影子协议逐轨迹相同。

此外，标签候选仍需通过阶段9.1的两类价值门槛：正常剖面相对 fixed10 保持至少5%的置信下界bit节省；启动发送器故障剖面相对 boot-event 保持clean改善且平均bit增长不超过20%。

开发使用每类80条轨迹、种子20261301；冻结后确认使用每类120条轨迹、种子20261401。若身份同步导致门槛失败，只记录负结果并定位原因，不回调故障参数。
