## 1. 研究问题

阶段9.2不继续优化心跳，而是回答：在旧恢复包、重复包、乱序包、序号回绕、双端重启和目录损坏出现时，接收端能否始终拒绝错误会话动作。

## 2. 三种身份方案

1. legacy_epoch_only：只使用现有目录版本和8 bit 更新序号。
2. restore_tag16_bounded：只在恢复帧增加16 bit 会话标签；普通更新和 ACK 继续使用8 bit 序号，但要求任何包的可投递寿命小于128次后续更新。
3. full_tag16：恢复帧、普通更新和 ACK 均携带16 bit 会话标签。

会话身份由发送端控制器代次、接收端 boot ID 和目录版本共同确定。

## 3. 冻结安全不变量

- 接收端可执行时，目录必须有效；
- 可执行动作必须来自当前接收端启动会话；
- 冷重启后短激活不得替代完整安装；
- 旧恢复包不得重新激活新的 boot 会话；
- 旧更新和错误目录更新不得替换动作；
- 旧 ACK 不得把发送端错误推进到 READY；
- 目录损坏后必须立即 fail-closed。

## 4. 模型检查方法

开发深度为6，确认深度为9。模型使用3 bit 缩减序号，使序号回绕能够在有限深度内出现，但使用与8 bit 部署序号相同的模运算规则。

预注册判断模式为：

- legacy 无界模型必须找到反例；
- restore_tag16 在包寿命有界时不得找到反例；
- restore_tag16 取消寿命界限后必须找到回绕反例；
- full_tag16 在相同无界攻击事件中不得找到反例。

该设计不是只追求“全部通过”。预期的反例是用于确认安全假设确实必要。

## 5. 开销门槛

按1000景、80次普通更新和5、20、50次恢复计算。restore_tag16 只为每次恢复增加16 bit，三个条件下均必须低于1 bit/景额外开销。

## 6. 证据边界

有界状态空间无反例不等于任意实现的数学证明。16 bit 标签在模型中视为无碰撞身份，不覆盖恶意伪造；真实实现必须加入最大包寿命、队列清理和完整性保护。
