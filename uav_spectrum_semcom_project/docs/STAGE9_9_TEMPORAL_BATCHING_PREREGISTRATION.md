# 阶段9.9：时间频谱条件下的B2/B4聚合预注册

## Material Passport

- 研究阶段：阶段9.9
- 实验类型：开发数据上的冻结比较，不是Final
- 数据来源：AERPAW Packapalooza 2023永久开发缓存
- 数据规模：364景、7个连续时间组
- 外部Final访问：禁止
- 预注册配置：`configs/stage9_9_temporal_batching_v1.json`

## 1. 研究问题

阶段9.8只证明了：如果458个更新可以理想地连续打包，B2和B4的更新路径bit理论上可分别降低约14.29%和21.40%。该计算没有回答在线接收端等待更新期间是否会执行过时动作。

阶段9.9检验：在真实连续频谱轨迹上，将原本应立即发送的任务动作更新推迟到第2个或第4个更新事件时，能否在明显降低H8更新路径bit的同时维持任务clean和regret。

## 2. 冻结比较方式

先用B1即时策略生成无损、因果的更新事件序列。B2和B4必须接收完全相同的更新项，不得增加、删除或重排：

- B1：每个事件立即发送；
- B2：累计2个事件后，在第2个事件所在景发送；
- B4：累计4个事件后，在第4个事件所在景发送；
- 接收端收到批次后只执行最新动作；
- 时间组末尾不足一个批次的更新仍计入bit，但在最后一景之后发送，不能倒推改善已经发生的任务结果；
- 不允许跨时间组打包，不允许预测未来频谱。

一个包含m个更新项的H8数据报占用：

`B(m) = 8 + 8 × ceil(42m ÷ 8) bit`

其中8 bit是H8固定模式头，42 bit是一个冻结普通更新的协议位宽，ceil表示向上取整到完整字节。

## 3. 数据拆分与任务

沿用阶段6已经冻结的时间组拆分：4组只用于拟合解析任务码本，3组只用于本次候选比较。任务规模为N = 8、16、32、64；三种连续块需求分别为0.25N、0.5N和0.75N；任务容差固定为ε = 0.2 dB。

## 4. 主要评价指标

- 更新路径bit及相对B1的降幅；
- clean rate；
- 平均最大查询regret；
- CVaR₀.₉(regret)；
- 过时动作景数；
- 更新事件实际等待景数和等待秒数；
- Markov突发丢包压力下相对B1的clean变化。

Markov丢包仅是配对压力测试，并非真实无人机链路概率。相同的逐景丢包掩码用于全部候选，以隔离“多个更新集中在一个数据报”带来的风险。

## 5. 保留门槛

B2或B4只有在四种N上全部满足以下条件才可保留：

1. 更新路径bit节省率的95%配对组bootstrap下界不低于5%；
2. 无损clean差值的95%下界不低于−0.5个百分点；
3. 平均regret增量的95%上界不高于0.02 dB；
4. 突发丢包clean差值的95%下界不低于−0.5个百分点。

任一条件失败，就不把批处理并入主架构，继续保留阶段9.8的 `S9-CH8-v1` 单更新实时发送方式。

## 6. 结论边界

本实验只能判断顺序动作流B2/B4在一个已见固定站点pilot数据上的开发价值。它不是外部Final，不验证真实无人机链路，不验证板载运行，也不能改变阶段6 Final失败的既有结论。
