# 阶段 S6R.3g：静默上下文恢复与固定心跳扫描报告

日期：2026-07-30
实验状态：开发扫描完成，候选已冻结
候选编号：S6R-FH10-v1
证据级别：主 Final 失败后的开发证据，不是新的 Final

## 1. 研究问题

阶段6R的24站点 ElectroSense 外部 Final 在四种信道规模上都保持了正的总 bit 节省和零错误码本动作，但 N = 16、32 的 clean rate 置信区间下界没有达到预注册的90%。失败输出与状态机行为共同指向一个具体机制：

> 当频谱动作长期稳定时，事件触发更新很少；若接收端在此期间丢失上下文，系统只能等待静默心跳恢复。N = 16、32 原工作点的16景心跳使连续不可用时间偏长。

本实验只检验：在不改变任务码本、任务容差、链路故障、激活协议和安全回退的条件下，缩短固定静默心跳能否恢复 clean 门槛，同时保留总 bit 正收益。

## 2. 预注册设计

### 2.1 数据边界

- 开发数据：4项既有 AERPAW 活动；
- 适配数据：4个已打开的 ElectroSense Pilot 站点；
- 已消费的24个主 Final 站点：不读取、不重跑；
- 6个确认锁箱站点：不读取；
- 3个储备站点：不读取。

运行后的访问计数为：

| 数据角色 | 访问次数 |
|---|---:|
| Pilot | 1 |
| 主 Final | 1 |
| 确认锁箱 | 0 |
| 储备 | 0 |

### 2.2 唯一干预变量

只改变 `heartbeat_silence_scenes`，按“最长间隔优先”比较16、10、8、6景。任务容差 ε = 0.2 dB、K = 4、码本、时间门控、64 bit版本化激活、最多两次激活、累计ACK、精确regret校验、escape、故障概率和精确动作基线全部保持冻结。

每个候选使用60条成对公共随机轨迹。置信区间采用5000次分层自举，先按活动或站点重采样，再按成对轨迹重采样。

### 2.3 选择门槛

一个候选必须在 N = 16 和 N = 32 上同时满足：

1. AERPAW与Pilot合并后的场景加权 clean 95%下界不低于90%；
2. Pilot单独的场景加权 clean 95%下界不低于90%；
3. 合并数据上的配对总 bit 节省95%下界大于0；
4. Pilot上的配对总 bit 节省95%下界大于0；
5. 错误码本动作执行次数为0。

若多个候选通过，则选择心跳最不频繁、即数值最大的候选，以避免为可靠性支付不必要的开销。

## 4. 冻结判定

预注册规则要求选择“通过全部门槛的最大间隔”。16景在两种 N 上都因 clean 下界不足而失败；10、8、6景全部通过。因此冻结：

> S6R-FH10-v1：N = 8、16、32、64 统一使用10景固定静默心跳。

其中 N = 8、64 与原 Final 工作点一致，只有 N = 16、32 从16景缩短为10景。没有改动语义码本、ε、上下文门控或故障参数。

## 5. 结果解释

10景相对16景表现出清晰的可靠性—开销交换：

- N = 16 的合并 clean 提高3.53个百分点，配对节省下降6.38个百分点；
- N = 32 的合并 clean 提高3.13个百分点，配对节省下降6.04个百分点；
- 两种 N 的 clean 与节省置信区间下界均越过预注册门槛；
- 继续缩短到8或6景能提高 clean，但会进一步消耗约3—11个百分点的节省，没有必要。

因此，当前问题可以由简单、可解释的固定心跳修复，不需要立即引入风险预测器或复杂AI看门狗。该结论只说明开发数据上的候选选择合理，尚不能证明其在未见站点上必然成立。

## 6. 严谨性与局限

### 6.1 已控制的风险

- 选择规则在执行前注册，避免事后挑点；
- 候选使用成对公共随机轨迹，减少链路随机差异；
- AERPAW与Pilot分别设门槛，避免合并平均掩盖Pilot失败；
- 主 Final、确认锁箱和储备值均未用于调参；
- 完整总 bit包含前向、ACK、心跳、安装、恢复、重复和escape；
- 错误码本动作必须严格为0。

### 6.2 仍然存在的限制

- 这是看到主 Final 失败后的开发实验，不能改写原 Final 的 `FAILED` 状态；
- Pilot只有4个站点，活动或站点层面的区间仍较宽；
- AERPAW与ElectroSense的采集机制不同，合并结果不是同分布总体估计；
- 固定10景是否对新的站点稳定，只能由未读锁箱或新独立数据检验；
- 该结果没有证明风险感知心跳无价值，只证明当前无需增加其复杂度。
