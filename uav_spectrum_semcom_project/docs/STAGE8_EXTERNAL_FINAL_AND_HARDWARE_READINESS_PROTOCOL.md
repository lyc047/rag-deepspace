# 阶段8.0：新独立外部验证与板载测试就绪协议

## 1. 本阶段的性质

阶段8.0不修改算法，也不运行新的Final。它只把未来验证的对象、数据独立性、统计方法、成功标准和失败处理提前固定下来。

被验证对象是已经冻结的 `S6R-FH10-v1`：

- K = 3任务等价码本；
- 版本化激活与累计ACK；
- 解析regret和最大年龄触发；
- 精确动作escape与完整安装回退；
- 固定10景静默心跳；
- 错误上下文下fail-closed。

阶段7冻结清单已经记录17项关键文件的SHA-256。阶段8执行前，必须先验证这些哈希不变。

## 2. 为什么不能立即再跑一次测试

阶段6 Final及其确认测试已经被消费且正式失败；阶段7没有新的独立外部Final。若继续在已见站点上修改、选择或验证，只能形成开发证据，不能恢复独立确认性。

因此，本阶段把研究活动分成三层：

1. 元数据预检：只看数据集版本、站点、日期、频率轴说明和许可证；
2. 执行冻结：冻结独立单元清单、信号路径、运行环境和统计脚本；
3. 单次信号访问：只在前两层完成后执行，访问后禁止调参和修改代码。

当前只完成第1层协议设计，尚未访问任何新信号。

## 3. 新外部Final的独立性要求

独立统计单元定义为“站点—活动”或“站点—日期会话”，不能把滑动窗口、故障轨迹或不同N当成独立样本。

最低要求为：

- 不少于20个新独立单元；
- 至少来自3个来源层，例如不同区域、活动或日期组；
- 任一来源层不超过总单元的60%；
- 阶段6已消费单元全部排除；
- 阶段7内部开发7站点和储备3站点继续关闭；
- 合成数据不计入Final样本量；
- 元数据不兼容或缺失时，记录并判失败，不临时替换为“更容易通过”的单元。

## 4. 冻结任务与公平比较

四种任务规模统一评估：

`N ∈ {8, 16, 32, 64}`

任务容差保持为：

`ε = 0.2 dB`

主比较对象是可靠精确动作包。两种方法必须使用：

- 相同的原始频谱场景；
- 相同的前向丢包、ACK丢失和接收端重置轨迹；
- 相同的会话长度；
- 相同的总bit记账边界；
- 相同的统计独立单元。

总开销必须包括前向、ACK、激活、心跳、escape、恢复和重传bit。只比较payload不能作为系统结论。

## 5. 主验收门槛

对每一种N均单独计算95%置信区间，并要求四种N全部通过：

1. 错误上下文动作执行次数为0；
2. 语义系统clean rate的95%区间下界不低于90%；
3. 相对精确动作包的clean差值区间下界不低于−0.5个百分点；
4. 总bit相对节省率的95%区间下界严格大于0。

总bit节省率按可读形式定义为：

`节省率 = 100% ×（精确包总bit − 语义系统总bit）÷ 精确包总bit`

clean差值定义为：

`clean差值 = 语义系统clean rate − 精确包clean rate`

主结论以独立单元为簇的10,000次配对bootstrap给出。故障轨迹采用共同随机数，避免把随机轨迹差异误当成算法差异。

## 6. 次要分析

以下结果必须报告，但不能推翻主门槛：

- clean目标为90%、95%和97%时的rate–risk前沿；
- 平均regret和条件CVaR；
- availability、escape率和恢复开销；
- 不同丢包、ACK丢失和重置条件下的退化速度；
- 各独立单元的结果与来源层差异；
- 10、100、1000和10000景会话的启动开销摊销。

如果总体结果由少数站点驱动，必须明确表述为异质性，而不能只报告合并均值。

## 7. 结果状态

Final只能产生三种状态：

- `PASSED`：四种N均通过全部主门槛；
- `FAILED`：完成有效执行，但至少一个N未通过；
- `INCONCLUSIVE`：数据适配、环境或执行失败，无法形成有效估计。

`FAILED`不能通过删除不利站点、改动阈值、挑选N或再次访问同一信号改写。`INCONCLUSIVE`也不能冒充Final成功或失败。

## 8. 板载测试协议

当前桌面CPU结果只能说明Python原型的在线codec较轻，不能称为无人机板载证据。目标处理器选定后，必须冻结：

- 板卡、CPU、操作系统和功耗模式；
- Python或编译运行时版本；
- 单线程设置；
- 电源和功耗测量方法；
- 完整运行脚本及其哈希。

每种N先预热1000景，再测量10000景，独立重复5次。记录p50、p95、p99时延、峰值RSS、存储、CPU利用率、每景能耗、温度和降频。

第一版工程门槛为：

- 在线编码加解码p95不超过10 ms；
- p99不超过20 ms；
- 峰值RSS不超过256 MiB；
- 冻结运行资产不超过1024 KiB；
- 错误上下文动作执行次数为0；
- 四种N全部通过。

功耗、冷启动和温度暂作为报告指标。目标板未冻结前，不设置主观功耗阈值，也不允许更换板卡来掩盖失败。
