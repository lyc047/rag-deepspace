## 1. 研究问题与冻结假设

S6R.3d 证明，阶段 S6R.3c 的完整码本安装与恢复开销会在短活动中抵消紧凑语义更新的收益，其中 ACK 丢失造成的恢复安装是第一大开销来源。本阶段只检验一个假设：

> 对接收端已经预装的已知码本，使用带版本和身份校验的 64 bit 激活消息代替重复完整安装，能否在不降低 clean rate、不允许错误码本动作执行的前提下，改善相同 clean 工作点下的总通信开销。

本阶段冻结 clean = 0.90 的原工作点、K = 4 码本、链路随机种子、60 条配对轨迹和全部统计方法，不重新选择动作元组，也不读取新的 Final 信号值。

## 2. 已实现协议

### 2.1 64 bit 激活帧

| 字段 | 位数 | 作用 |
|---|---:|---|
| magic | 8 | 帧类型与基本完整性识别 |
| version | 2 | 激活协议版本 |
| node ID | 6 | 节点身份 |
| catalog epoch | 8 | 预装目录版本 |
| bank ID | 8 | 码本目录索引 |
| codebook epoch | 8 | 码本版本 |
| codebook tag | 16 | 完整清单 SHA-256 的前 16 bit，会话内快速身份保护 |
| activation epoch | 8 | 本次激活序号 |
| 合计 | 64 | 固定宽度 |

完整 SHA-256 在目录预置时校验；16 bit tag 只承担会话内身份保护，不能替代目录配置阶段的完整哈希。

### 2.2 接收与回退规则

接收端只有在以下条件全部满足时才激活码本：

1. 帧宽、magic 和协议版本有效；
2. catalog epoch 一致；
3. bank ID 存在；
4. codebook epoch 可接受；
5. codebook tag 与预装完整清单一致。

激活成功后，接收端发送现有 24 bit 累计 ACK。若目录、bank、epoch 或 tag 任一失配，接收端拒绝激活且不发送 ACK；发送端最多尝试两次，随后强制回退到完整码本安装。OOD 适配码本在 v1 中始终使用完整安装。任何未确认激活之前到达的紧凑更新均被拒绝，因此错误码本动作执行次数的设计目标为 0。

### 2.3 工程实现边界

- 预装目录保存在接收端非易失存储中，注册的“上下文重置”不会清除目录；
- 非易失目录损坏或整机丢失不在 v1 故障模型内，出现时必须完整重新配置；
- 激活与紧凑更新共享模 256 的 epoch 命名空间；
- 完整阶段6模拟器保持冻结，本阶段使用独立的相邻可靠性模拟器接入新协议。

## 3. 实验设计

### 3.1 数据与分组

验证使用既有四项 AERPAW 开发活动，不增加数据访问：

- AERPAW Packapalooza 2023；
- AERPAW Lake Wheeler 2024；
- AERPAW Packapalooza 2024；
- AERPAW Packapalooza 2025。

每项活动按时间顺序划分为不重叠会话。每段会话都从空上下文开始，但已知码本目录保留。会话长度取 20、50、100 景和整活动。2023 活动保持 OOD 决策并走完整安装，其余已知 BANK 决策才使用 64 bit 激活。

### 3.2 比较对象与计费

主比较为：

- 激活协议语义系统；
- 逐景精确动作基线。

同时保留 S6R.3c 的完整清单安装语义系统作为历史参照。所有方法统一计入前向帧、ACK、心跳、安装、恢复、重复和回退开销，指标为总 bit/景。激活协议与原完整安装方案使用相同链路随机轨迹，并比较 clean rate 是否发生损失。

### 3.3 统计方法

- 每个 N 使用 60 条配对蒙特卡洛链路轨迹；
- N 取 8、16、32、64；
- 使用共同随机数降低协议间比较方差；
- 对配对节省率执行 5,000 次 bootstrap；
- 同时报告场景加权结果与四活动等权宏平均；
- 主要门槛要求整活动场景加权节省率的 95% 区间下界在四个 N 上均大于 0，且错误码本执行次数为 0。

## 4. 主要结果

### 4.1 整活动结果

相对逐景精确动作基线：

| N | 激活协议总 bit/景 | 激活协议节省率 | 95% 区间 | 等活动宏平均节省率 | 原完整安装节省率 | 激活带来的增益 |
|---:|---:|---:|---:|---:|---:|---:|
| 8 | 41.78 | 25.40% | [23.61%, 27.15%] | 30.04% | 3.61% | +21.79 个百分点 |
| 16 | 46.10 | 21.87% | [20.06%, 23.63%] | 15.77% | 4.83% | +17.05 个百分点 |
| 32 | 46.61 | 24.82% | [23.46%, 26.21%] | 18.54% | 8.29% | +16.53 个百分点 |
| 64 | 44.92 | 30.89% | [29.03%, 32.68%] | 38.18% | 10.58% | +20.31 个百分点 |

四个 N 的场景加权与等活动宏平均区间下界均为正。与完整安装方案相比，激活协议将整活动节省率提高了 16.53—21.79 个百分点。

### 4.2 任务可靠性与安全性

- 激活协议与原完整安装语义系统的 clean rate 逐 N 完全一致，clean 损失均为 0；
- 四种 N、全部活动、全部会话长度的错误码本动作执行次数均为 0；
- 所有总 bit 账本恒等式成立；
- OOD 活动没有错误使用短激活消息；
- 外部 Final 访问计数未变化。

这些结果说明本阶段改进来自上下文建立与恢复开销下降，而不是放松任务可靠性或删除计费项。

### 4.3 冷启动会话边界

场景加权节省率如下：

| 会话长度 | N = 8 | N = 16 | N = 32 | N = 64 |
|---:|---:|---:|---:|---:|
| 20 景 | −13.83% | −34.36% | −30.41% | −5.81% |
| 50 景 | 9.59% | −3.98% | 0.53% | 18.14% |
| 100 景 | 19.44% | 12.61% | 15.45% | 25.63% |
| 整活动 | 25.40% | 21.87% | 24.82% | 30.89% |

按“95% 区间下界大于 0”判断，N = 8 和 N = 64 的最短稳定正收益会话为 50 景；N = 16 和 N = 32 为 100 景。N = 32 在 50 景时点估计为正，但区间为 [−0.92%, 1.96%]，不能判定为稳定正收益。

因此，本协议适合中长会话或可跨任务保留预装目录的系统，不应宣称对所有短会话均节省 bit。

### 4.4 活动异质性

整活动下，15 个“N × 活动”组合具有正点估计；唯一例外是 N = 16 的 AERPAW Packapalooza 2025，节省率为 −0.38%，95% 区间为 [−3.08%, 2.06%]。该结果必须保留，说明 N = 16 的特定活动仍处于收益边界。

2023 活动因被判为 OOD，仍使用完整安装。其正收益不能归因于短激活协议，而来自原有事件触发语义更新；这防止把 OOD 分支收益错误归入新协议。

## 7. 阶段判断

S6R.3e 通过冻结的开发验收门槛，64 bit 版本化码本激活协议应保留为阶段6R的新候选架构。相较 S6R.3c，它解决了“总体正收益被单个长活动主导”和“完整恢复安装过重”两个主要问题，并把整活动 matched-clean 节省提高到约 22%—31%。

但当前不能宣布阶段6最终完成，原因有三点：

1. 结果仍来自同四项开发活动，不是新的独立外部 Final；
2. 20 景冷启动会话仍全部为负；
3. N = 16 的 2025 活动仍没有稳定正收益。

## 8. 下一步

阶段6R下一步转入 S6R.3f“外部确认协议冻结”，不是继续在这四项活动上调整激活字段或重选工作点：

1. 冻结当前 64 bit 帧格式、两次尝试上限、完整安装回退和 clean = 0.90 工作点；
2. 为全新未读信号数据预注册适配规则、活动级统计单位和 matched-clean 判据；
3. 将“整活动场景加权节省下界为正、等活动宏平均不为负、错误码本执行为 0”设为主门槛；
4. 将 20/50/100 景冷启动结果设为预先声明的次要边界指标；
5. 在新外部数据到位前，只允许做代码审计、硬件资源测量和不读取新信号值的数据完整性核验；
6. 外部确认通过后，再恢复多步任务失效预测研究；若失败，则依据失败活动、OOD 比例和会话长度归因，不回调本阶段开发数据追正。
