## 1. 目的

S5.4证明了多查询块索引在大信道规模下具有协议bit优势，但没有回答事件触发状态在频谱快速变化时是否安全。S5.5保持τᵣ = 0.2 dB和Aₘₐₓ = 120 min不变，检验多查询事件包在渐变和突变频谱下的平均regret、CVaR₀.₉与实际bit。

## 2. 压力轨迹

原始输入仍是已经使用过的N = 8固定站点AERPAW validation功率序列。本实验生成四种轨迹：

1. `observed`：不改变原始功率；
2. `gradual_drift`：每个站点内从序列开始到结束逐渐加入边缘最大±3 dB的频率斜率；
3. `abrupt_band_hop`：每12景将频谱循环移动3个信道；
4. `burst_block_interference`：每20景的前4景对连续3个信道增加8 dB干扰，干扰块位置按固定步长移动。

这些变换是确定性的算法压力测试，不是真实测得的渐变、跳频或干扰事件。

查询序列同时覆盖：

- `cyclic`：D按2 → 4 → 6逐景切换；
- `markov`：需求保持概率为0.7的持续型查询。

链路、重复次数、共同随机数、bootstrap和比较方法与S5.3一致。阈值没有因压力结果重新搜索。

| 渐变 | markov | 54.14% | −0.00162 | 0.00689 | −0.07127 | −0.00269 | 42.6% | 通过 |

- 实际bit至少降低30%；

## 4. 机制解释

### 4.1 渐变没有迫使算法频繁发送

渐变轨迹的上报率下降到42.6%—43.5%，而不是上升。原因是缓慢斜率并不必然改变当前查询的最优块；事件触发直接检查复用旧块造成的任务代价，而不是看到功率数值变化就发送。

### 4.2 频段跃迁是当前最困难条件

`abrupt_band_hop + markov`的平均regret差为0.00180 dB，平均差上界0.01057 dB；CVaR差上界达到0.04271 dB，最接近0.05 dB门槛。它仍通过，但说明“突变发生时当前查询未及时触发，随后查询又切换”的组合是下一步应重点检查的状态风险。

### 4.3 块干扰下多查询刷新降低尾部风险

短时连续块干扰使每景单查询方法在丢包后的旧状态更容易失效；成功的多查询包同时刷新三种需求，因而其CVaR反而明显较低。这是受控压力机制，不代表真实干扰环境一定获得同等改善。

## 6. 当前结论

可以陈述：

> 在已经见过的N = 8固定站点功率序列及四种预注册确定性压力轨迹中，固定多查询事件包在不重新调参的情况下均降低46.76%—54.14%的实际bit，并保持平均regret与CVaR₀.₉的开发非劣门槛。

不能陈述：

- 已经在新的真实突变频谱上验证；
- 已经证明移动、多用户或宽带64信道任务鲁棒性；
- ACK不同步和发送端—接收端状态分叉已经解决；
- 已完成独立Final。
