## 1. 冻结目的

S6.7c已经证明冻结R1 V2架构在2022开发数据的较宽任务范围内具有matched-clean正bit收益。S6.7d的任务是在读取任何2024—2025外部信号值之前，固定候选、数据适配、统计方法、成功门槛和失败处理规则。

冻结完成后不再允许根据外部结果修改：

- 任务容差ε；
- 查询集合；
- 码本拟合规则；
- 心跳、状态年龄和重复发送参数；
- 精确动作基线；
- clean工作点；
- bootstrap方法；
- 场景选择和异常处理规则。

## 2. 数据与采样

外部Final使用三个未参与开发的空中频谱活动：

- 2024 Packapalooza城市活动67景；
- 2024 Lake Wheeler乡村活动67景；
- 2025 Packapalooza城市活动66景。

总计200景。场景仅依据压缩包文件名中的时间戳选择，相邻场景至少间隔5分钟，并按活动分别分层。选择过程不得读取功率值、频谱特征或任何方法输出。

频谱适配固定为3550—3700 MHz。该频段划分为N＝8、16、32、64个信道，连续块需求分别约为N的25%、50%和75%。若场景在访问后出现损坏或不兼容，不得用其他场景替换；应保留为Final执行失败或数据适配失败。

## 3. 冻结算法

主要算法为R1 V2“持久码本＋紧凑动作刷新”：

- 码本只利用永久排除的2023试点数据拟合；
- 码本保存在非易失存储中；
- 普通接收端重置只清空当前动作缓存；
- 心跳静默间隔为10景；
- 最大动作状态年龄为30分钟；
- 任务更新发送2次；
- 更新预留比例为0；
- 无法由码字安全覆盖的状态使用escape加精确动作回退；
- 错误码本身份必须拒绝执行。

任务容差固定为ε＝0.2 dB，查询集合固定为25%、50%和75%三个连续块需求。

## 4. 公平基线与统计

精确动作基线每景发送完整三查询动作包，并分别评估1、2、3次开放环发送。语义方案与精确基线使用相同场景、相同故障概率和配对随机数。

冻结故障条件为：

- 任务包丢失概率0.10；
- ACK丢失概率0.20；
- 延迟重复概率0.10；
- 接收端动作缓存重置概率0.02；
- 安装包丢失概率0.10。

这些故障是受控注入，不是外部数据集直接测得的真实回传链路。

统计外层单位为活动，内层单位为配对链路轨迹。每个N执行60条轨迹，bootstrap重复5,000次，置信度为95%。主要clean目标为90%，85%只作为辅助。开发阶段没有共同可达的95%和97%工作点，因此不把二者加入Final假设。

## 5. 预注册成功门槛

主要配置为N＝8、ε＝0.2 dB、三查询和90% clean。它必须同时满足：

1. 语义方案clean率95%置信下界不低于90%；
2. 相对满足相同clean目标且bit最低的精确动作基线，配对总bit节省率95%置信下界大于0；
3. 分别排除任一外部活动后，bit节省点估计仍为正；
4. 错误码本动作执行次数为0。

若通过且bit节省点估计不低于15%，记为强效果。

规模支持要求N＝8、16、32、64中至少三个通过上述主要门槛。只有N＝8主配置通过、规模支持通过、三个活动均完整保留且所有N的错误码本动作次数为0，才判定阶段6外部价值得到支持。

## 6. 一次性访问规则

执行顺序固定为：

1. 核对四个压缩包的大小与SHA-256，不读取信号值；
2. 运行2023排除试点演练和完整回归测试；
3. 生成代码快照；
4. 用文件名和时间戳生成200景目录；
5. 运行无信号预检；
6. 原子地把访问次数从0改为1，并同时作废旧阶段5访问入口；
7. 加载一次外部信号并运行全部注册方法；
8. 生成原始结果和统计分析；
9. 无论成功、失败或崩溃，访问次数不得重置。

Final结果不得用于调整本次受评算法。若失败，只能进行失败归因；任何改进必须使用新的独立外部数据验证。
