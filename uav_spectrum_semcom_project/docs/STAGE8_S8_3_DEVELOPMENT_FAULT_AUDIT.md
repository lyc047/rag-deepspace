# 阶段8 S8.3：公开数据开发侧故障审计

## 1. AADM真实链路结果

开发侧共读取13次物理试飞，确认侧20次试飞保持零访问。LoRa日志按去重包编号合并多个网关接收记录，再按时间顺序检测帧计数器重启。每个单调计数段内，位于最小与最大已接收计数器之间但未出现的帧定义为“内部缺失帧”。

主要结果如下：

| 指标 | 开发侧结果 |
|---|---:|
| 独立试飞数 | 13 |
| 接收的唯一包 | 1767 |
| 可重构内部帧区间 | 2512 |
| 内部缺失帧 | 745 |
| 合并丢失率下界 | 29.66% |
| 飞行级聚类自助法95%区间 | 11.95%—47.45% |
| 存在内部缺失的飞行 | 8/13 |
| 出现LoRa发送端计数重启的飞行 | 4/13 |
| 最长连续缺失 | 20帧 |

该结果不支持“所有会话均具有固定10%独立丢包率”的模型。13次飞行的丢失率范围为0%—78.38%，飞行间差异明显。

但短时结构需要更谨慎解释。各单调计数段的一阶失败相关系数绝对值最大为0.084，未超过预注册阈值0.1。因此，开发数据支持的不是单一Gilbert–Elliott突发模型，而是：

> 飞行间丢失率高度异质，但在单个计数段内部，短时独立伯努利近似尚未被一阶相关诊断否定。

这也是为什么后续冻结“飞行层次伯努利模型”，而没有直接采用把所有飞行混合后的两状态Markov参数。把低丢包飞行和高丢包飞行直接汇总会人为制造较强的持续性，是需要避免的聚合谬误。

## 2. ALFA板载日志结果

开发侧注册19次原始飞行，其中16次存在processed数据，共读取23个加工片段；同一原始飞行的多个片段始终作为同一统计簇。确认侧20次原始飞行、raw bag、telemetry和dataflash值均保持零访问。

主要结果如下：

| 指标 | 开发侧结果 |
|---|---:|
| 有processed覆盖的原始飞行 | 16/19 |
| processed片段 | 23 |
| 合并去重后的观察时长 | 0.679小时 |
| MAVLink SYSTEM_TIME启动时间样本 | 3802 |
| 可检测的飞控启动时间回退 | 0 |
| MAVROS断开样本 | 0 |
| MAVROS重新连接 | 0 |
| MAVLink大时间间隔 | 0 |

MAVLink的SYSTEM_TIME消息提供了 `time_boot_ms`，因此“飞控在片段内重启”在技术上可观测。本开发集中没有检测到该标记。然而观察时间不足1小时，零事件对应的描述性Poisson 95%上限仍约为每小时4.41次，约束很弱。

更重要的是，ALFA观测对象是Pixhawk、MAVLink和ROS加工片段，而不是本项目语义接收端进程、码本目录或动作缓存。因此：

- 不能把0次飞控重启写成0次语义上下文重置；
- 不能据此把每景2%的上下文重置概率称为真实标定值；
- 2%只能继续作为保守压力点；
- LoRa发送端帧计数器重启也不等价于接收端语义上下文丢失。

## 3. 冻结的开发故障模型

阶段8后续机制重放采用飞行层次伯努利模型：

1. 对每条“频谱会话—蒙特卡洛轨迹”，从13次AADM开发飞行中等概率抽取一次飞行；
2. 取该飞行的内部缺失率下界 pᶠ；
3. 在该轨迹内，以 pᶠ 作为任务更新包和心跳请求的丢失概率；
4. 安装丢失率仍固定为10%；
5. ACK与心跳响应丢失率仍固定为20%；
6. 上下文重置率仍固定为每景2%；
7. 后三项均明确标记为未标定压力参数。

冻结模型的开发飞行平均丢失率为27.81%，但重放不会用这一均值替代各飞行，而是保留会话间异质性。

## 4. 阶段性结论

本阶段形成两个有效结论：

1. 先前固定10%同质独立丢包模型过于简单，至少应加入“会话级链路质量异质性”；
2. 当前公开数据不能标定语义接收端上下文重置，阶段7的2%随机重置只能被解释为压力测试，不是现实故障率。

因此，阶段8后续重放的目标不是证明公开数据等同于板载环境，而是判断固定10景心跳在更真实的链路异质性下是否仍具有优势，并明确真正板载验证必须记录哪些状态。
