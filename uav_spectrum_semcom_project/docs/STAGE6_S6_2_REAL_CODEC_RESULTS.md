## 1. 目标

S6.1只统计了码本payload。S6.2实现可实际编解码的版本化bitstream，检验加入码本身份、状态同步和回退字段后，阶段六相对阶段五是否仍有真实应用层比特优势。

## 2. 协议结构

每个阶段六任务码字包包含：

- 8-bit魔数；
- 3-bit协议版本；
- 2-bit消息类型；
- 8-bit节点标识；
- 3-bit查询数量；
- 8-bit码本epoch；
- 16-bit码本标签；
- 2-bit任务码字符号；
- 如码字不能安全覆盖，则追加精确多查询动作。

当前最小应用头为48 bit。码本安装时验证完整SHA-256，数据包内携带16-bit截断标签，用于检测常规的旧码本或错误上下文。该标签不是密码学认证，不能宣称抵抗主动碰撞攻击。

接收端只有在以下条件全部成立时才解码：

1. 魔数、版本和消息类型正确；
2. 查询数量与本地码本一致；
3. 码本epoch一致；
4. 16-bit码本标签一致；
5. payload长度与符号模式完全一致；
6. 逃逸动作落在已登记动作集合内。

任一检查失败均拒绝解码。

## 3. 数据和划分

沿用S6.1的固定开发协议：

- 197个训练场景、4个完整15分钟时间簇；
- 167个隔离评估场景、3个完整15分钟时间簇；
- N取8、16、32和64；
- 查询需求为N的1/4、1/2和3/4；
- ε固定为0.2 dB；
- 码本仍为3个码字，另保留1个逃逸符号。

## 4. 真实码流结果

隔离评估的668次编解码全部逐bit往返成功，码本覆盖率均为100%，未触发逃逸回退。

| N | 阶段五精确查询包 | 阶段六真实任务码字包 | 阶段六相对降幅 | 最大regret |
|---:|---:|---:|---:|---:|
| 8 | 48 bit | 50 bit | −4.17% | 0.14478 dB |
| 16 | 51 bit | 50 bit | 1.96% | 0.14516 dB |
| 32 | 54 bit | 50 bit | 7.41% | 0.16267 dB |
| 64 | 57 bit | 50 bit | 12.28% | 0.16269 dB |

其中负降幅表示阶段六使用更多比特。

## 5. 结果解释

S6.1的75%—88.24%是payload降幅，不是完整数据包降幅。S6.2加入8 bit额外身份开销后，得到更接近真实协议的结论：

- N=8为负结果，码本身份开销超过payload节省；
- N=16只有很小优势；
- N=32出现中等优势，但尚未达到10%；
- N=64达到12.28%，说明候选空间较大时码本仍有应用层价值；
- 所有规模的任务风险继续受0.2 dB硬约束。

因此，论文中必须分别报告payload和完整应用层bit，不能使用payload降幅代替端到端通信收益。

## 6. 新的研究方向

S6.3不应继续单纯缩小码本，而应优先解决协议开销摊销：

1. 在会话建立时发送完整码本SHA-256；
2. 稳定会话内复用码本上下文，不在每个任务包重复发送全部身份信息；
3. 周期性或风险触发发送上下文确认包；
4. 普通任务包只携带短epoch或短上下文标识；
5. 接收端不确定时立即使用精确绝对更新；
6. 将上下文刷新与阶段五事件触发、状态年龄和ACK信念集合联合。

该方案必须比较“每包48-bit身份头”和“会话摊销身份开销”两种真实协议，并统计上下文刷新频率，不能假设码本身份传输免费。

## 7. 结论边界

本轮证明了真实编解码可行，并识别出小N协议开销负收益边界。尚未证明：

- 码本在随机误码链路上可靠；
- 16-bit标签具有安全认证能力；
- 上下文摊销后必然节省总比特；
- 跨活动码本覆盖率；
- 阶段六Final性能。
