# 阶段6R完整可靠性协议重接入报告

## 1. 研究目的

本阶段回答一个比 payload-only 覆盖率更严格的问题：

> 在计入校准精确包、码本安装、恢复安装、紧凑更新、escape、重复、ACK 和心跳后，阶段6R的时序码本机制在相同 clean 约束下是否仍能降低总通信开销？

本阶段只使用已经消费并转为 development-only 的 2023—2025 缓存，不访问新的 Final 信号值。

## 2. 冻结架构

完整会话按以下顺序运行：

1. 发送端在校准前缀逐景发送自包含的多查询精确动作包；
2. 时序一致性门控使用连续窗口判断已知活动码本或 OOD；
3. 已知活动复用现有码本动作，OOD 使用校准前缀进行解析贪心构造；
4. 无论码本来源如何，本轮均发送完整且带 SHA-256 身份校验的安装包；
5. 安装成功后进入阶段6冻结的事件触发语义更新；
6. 接收端使用累计 ACK、上下文信念、固定静默心跳和恢复安装；
7. 每个紧凑动作在发送前接受精确 regret 校验，不满足 ε = 0.2 dB 时发送 escape 加精确动作；
8. 接收端上下文不匹配时拒绝紧凑包，不执行可能错误的动作。

本轮没有把“预装码本只需 8 bit 选择”计入结果。原因是当前尚无版本化、可确认、可恢复的短码本激活协议。直接计入 8 bit 会低估实际可靠性开销。

## 3. 消息和 bit 口径

主指标为：

总应用 bit = 前向应用 bit + 反馈应用 bit

其中：

- 前向应用 bit包括校准精确包、初始安装、恢复安装、紧凑更新、escape、重复副本和心跳请求；
- 反馈应用 bit包括累计 ACK 和心跳响应；
- 本轮不启用预留保护，因此资源等效 bit与总应用 bit相同；
- exact 基线每景发送自包含的当前多查询精确动作，不依赖码本和接收端上下文；
- matched-clean 比较只使用真实仿真工作点，不插值。

## 4. 软件实现

新增实现包括：

- `src/spectrum_semcom/stage6r_reliability_integration.py`
  - 从冻结动作元组构造确定性码本；
  - 校验查询动作字母表与训练覆盖；
  - 将校准精确轨迹和语义后缀轨迹组合为统一账本；
  - 保留冻结阶段6可靠性状态机。
- `tests/test_stage6r_reliability_integration.py`
  - 校准覆盖；
  - 重复动作拒绝；
  - 校准精确 bit、完整安装 bit和总账恒等式。
- `configs/stage6r_full_protocol_dry_run_v1.json`
  - 在执行前冻结协议、故障条件、工作点和验收门。
- `scripts/run_stage6r_full_protocol_dry_run.py`
  - 运行配对蒙特卡洛；
  - 输出组件级 bit分解；
  - 进行 matched-clean 非插值选择。

新增测试与既有阶段6可靠性测试共 12 项，全部通过。

## 5. 开发演练设置

数据活动：

- AERPAW Packapalooza 2023；
- AERPAW Lake Wheeler 2024；
- AERPAW Packapalooza 2024；
- AERPAW Packapalooza 2025。

任务规模：

- N ∈ {8, 16, 32, 64}；
- 需求比例为 0.25、0.50、0.75；
- 每个 N 共 564 景；
- 精确动作帧分别为 56、59、62、65 bit。

主故障条件：

- 安装丢失率 10%；
- 任务包丢失率 10%；
- ACK 丢失率 20%；
- 延迟重复 ACK 概率 10%；
- 接收端上下文重置概率 2%。

本轮为 12 条配对蒙特卡洛轨迹的小规模协议演练，作用是决定是否进入更大的可靠性扫描，不承担确认性结论。

## 6. 结果

### 6.1 无故障链路

| N | 语义总 bit/景 | 精确基线 bit/景 | 节省比例 |
|---:|---:|---:|---:|
| 8 | 13.88 | 56.00 | 75.21% |
| 16 | 15.85 | 59.00 | 73.14% |
| 32 | 16.42 | 62.00 | 73.52% |
| 64 | 16.49 | 65.00 | 74.63% |

四种 N 的 clean 均为 100%。这说明码本安装、校准和完整帧头计入后，在理想链路上仍有明确开销优势。

| N | 语义 clean | 语义总 bit/景 | 精确 bit/景 | 配对节省 | 95%区间 |

当前小网格没有语义工作点达到 clean 95%下界不低于 0.95。

### 6.3 bit瓶颈

clean 0.90 工作点中，恢复安装约占：

- N = 8：22.58 bit/景；
- N = 16：31.70 bit/景；
- N = 32：32.72 bit/景；
- N = 64：32.82 bit/景。

相比之下，紧凑更新仅约 7.34—8.97 bit/景。由此可见，当前限制高可靠性收益的主要因素不是码字宽度，也不是轻量排序器精度，而是：

> ACK 不确定性与接收端重置假设触发的重复上下文恢复。

这也解释了为什么 payload-only 结果很强，而 matched-clean 总 bit优势在 clean 0.90 时明显缩小。

## 7. 客观结论

本轮支持以下结论：

1. 阶段6R码本机制已能接入完整可靠性状态机；
2. 所有 bit恒等式闭合，错误码本动作执行次数为 0；
3. 无故障链路下总 bit优势明确；
4. 主故障条件、clean 0.85 下四种 N 都有统计显著节省；
5. clean 0.90 下，较大规模 N = 32、64 已出现统计上为正的总 bit节省；
6. N = 8、16 的 clean 0.90 优势尚不确定；
7. 当前证据不支持 clean 0.95 的高可靠性结论；
8. 轻量排序器不是当前主要瓶颈，不应在同一数据上继续调参；
9. 恢复安装是下一步协议研究的核心对象。

本轮不能支持以下表述：

- “阶段6R已经通过外部 Final”；
- “所有规模在 clean 0.90 下都显著优于精确基线”；
- “系统已经满足 clean 0.95 高可靠性要求”；
- “只需 8 bit 即可可靠切换预装码本”。

## 8. 下一步决策

开发演练已经通过扩大扫描的入口门。下一步冻结并执行：

1. 心跳静默间隔：4、6、8、10、12、16、20、30和关闭；
2. 最大状态年龄：30、60、120分钟；
3. 任务包开放环尝试次数：1、2、3；
4. 60 条配对蒙特卡洛轨迹；
5. clean 目标：0.85、0.90、0.92、0.95、0.97；
6. 对恢复安装、心跳、ACK、重复、紧凑更新和escape分别计费。

若扩大扫描仍不能在 clean 0.95 下形成共同工作区，则不再靠扩大码本或调轻量模型解决，而应单独设计并验证版本化的预装码本激活或低成本上下文存活确认协议。

## 10. 扩大 matched-clean 扫描结果

### 10.1 执行完整性

扩大扫描使用执行前注册的 81 个语义工作点、3 个精确工作点和 60 条配对链路轨迹。四种 N 作为独立分片并行执行，合并前强制检查配置哈希、输入哈希、Final 访问状态和 N 分片互斥性。

全部检查通过：

- 四种 N 均完成；
- 所有 bit恒等式成立；
- 错误码本动作执行次数为 0；
- 分片身份检查通过；
- Final 访问状态保持 `access_consumed_final_execution_failed`；
- Final 访问次数保持 1。

### 10.2 matched-clean 总 bit结果

| clean目标 | N = 8 | N = 16 | N = 32 | N = 64 |
|---:|---:|---:|---:|---:|
| 0.85 | 15.08% [12.75%, 17.31%] | 16.66% [14.28%, 19.03%] | 20.84% [18.98%, 22.67%] | 22.85% [20.80%, 24.88%] |
| 0.90 | 3.61% [1.20%, 6.03%] | 4.83% [2.57%, 7.10%] | 8.29% [6.44%, 10.16%] | 10.58% [8.20%, 12.85%] |
| 0.92 | −8.16% [−10.70%, −5.71%] | −4.06% [−6.41%, −1.76%] | 1.48% [−0.35%, 3.34%] | −1.27% [−3.63%, 0.97%] |
| 0.95 | −41.20% [−44.43%, −38.07%] | −35.61% [−38.57%, −32.70%] | −31.30% [−33.62%, −28.91%] | −30.21% [−32.65%, −27.74%] |
| 0.97 | 无语义工作点 | 无语义工作点 | 无语义工作点 | 无语义工作点 |

方括号内为配对链路蒙特卡洛 95%区间。该区间描述链路随机性，不等价于跨活动总体置信区间。

### 10.3 主要验收判断

按照执行前登记规则：

- primary success：通过。clean不低于 0.90 时，四种 N 的总 bit节省下界均高于 0；
- strong effect：未通过。clean不低于 0.90 时，没有 N 达到 15%平均节省；
- high reliability support：部分通过。四种 N 都存在 clean下界不低于 0.95 的真实工作点，但这些工作点的总 bit显著高于精确基线；
- clean 0.97：不支持。

因此，本阶段的严谨结论是：

> 阶段6R在中等可靠性目标 clean = 0.90 下已经形成稳定且随 N 增长而扩大的总 bit优势，但在 clean ≥ 0.92 时优势消失，在 clean = 0.95 时可靠性维护开销明显超过精确基线。

### 10.4 为什么高可靠性下转为负收益

clean = 0.90 的入选工作点中，恢复安装约为 22.6—32.5 bit/景；clean = 0.95 时进一步升至约 36.2—39.3 bit/景，同时还需要更频繁心跳和部分双发。

clean = 0.95 的代表工作点通常采用：

- 心跳静默间隔 4 景；
- 最大状态年龄 120分钟；
- 任务包尝试 2 次。

高可靠性通过“更频繁确认 + 更多恢复 + 重复任务包”实现，因此语义 payload 的压缩收益被可靠性协议开销反超。

### 10.5 规模效应

clean = 0.90 时，节省比例随 N 增长：

3.61% → 4.83% → 8.29% → 10.58%

这与理论预期一致：精确动作包随候选动作空间增长，而紧凑码字宽度变化较慢。但该趋势目前只有四个 N 和四个已开发活动支撑，仍需逐活动分析与新外部数据确认。

## 11. 扫描后的主线决策

S6R.3c 的“完整协议可运行”和“clean 0.90 下正收益”目标已经完成，但高可靠性边界仍是明确缺陷。下一阶段设为 S6R.3d，顺序如下：

1. 对 clean = 0.90 的入选点做逐活动结果和留一活动敏感性分析；
2. 检查优势是否由 2023 长会话单独主导；
3. 量化会话长度对安装摊销的影响；
4. 将恢复安装拆分为真实重置触发、ACK不确定性触发和心跳失败触发；
5. 设计版本化预装码本激活协议，但在实现前不计入任何短选择收益；
6. 仅当新协议在相同 clean 下改善总 bit时保留；
7. 完成后再冻结新的确认性外部数据协议。

轻量 Ridge、树模型和 MLP 排序器继续保持负结果冻结。现阶段继续增加模型复杂度不能解决 30 bit/景量级的恢复安装瓶颈。
