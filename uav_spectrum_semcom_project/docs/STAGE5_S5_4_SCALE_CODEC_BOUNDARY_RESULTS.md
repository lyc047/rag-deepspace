## 1. 研究问题

S5.3证明多查询语义包能用一次成功传输刷新多个带宽需求状态，但只验证了N = 8、查询集合D ∈ {2, 4, 6}和40 bit应用头。本实验回答三个边界问题：

1. 当信道数N增加时，多查询块索引相对4-bit逐信道软功率的实际bit优势如何变化；
2. 当查询数量由3个增加到5个和7个时，语义包何时跨越对齐或FEC边界；
3. 40 bit紧凑头、152 bit兼容头以及不同FEC是否改变结论。

本实验不把8信道测量数据拼接成“真实64信道数据”。因此本阶段只验证codec和仿真回传链路成本，不检验N = 16、32、64时的regret泛化。

## 2. 冻结实验设计

### 2.1 信道与查询规模

- 信道数：N ∈ {8, 16, 32, 64}；
- q3查询族：D/N ∈ {1/4, 1/2, 3/4}；
- q5查询族：D/N ∈ {1/8, 1/4, 1/2, 3/4, 7/8}；
- q7查询族：D/N ∈ {1/8, 1/4, 3/8, 1/2, 5/8, 3/4, 7/8}；
- 应用头：40 bit和152 bit；
- FEC：无FEC、Hamming(7,4)、三重复码。

第D个需求的候选连续块数量为：

M(D) = N − D + 1

对应绝对索引宽度为：

b(D) = ⌈log₂ M(D)⌉

一个多查询包的应用层长度为：

B(bundle) = B(header) + Σ[D属于查询集合] b(D)

### 2.2 公平比较对象

- `single_index_mean`：一次只发送当前查询索引，成本对所有查询等权平均；
- `bundle_all_queries`：一个包携带全部查询索引；
- `separate_indices_all_queries`：每个查询分别发送一个独立包；
- `occupancy_vector_all_queries`：发送N-bit占用向量；
- `soft_power_all_queries`：每信道4 bit软功率。

“全部查询”方法都能从一次语义操作恢复整个冻结查询集合；单查询索引只恢复当前查询，因此同时报告事件率盈亏平衡点，不能只比较单次包长。

### 2.3 数字链路

每个应用报文继续经过阶段2冻结链路的96 bit链路头、16 bit CRC、对齐、FEC、QPSK和最多一次重传。链路覆盖AWGN、Rayleigh、Rician，Eᵦ/N₀ ∈ {0, 3, 6, 9} dB，每个条件100次共同随机数重复。

完整矩阵包含4320个聚合单元和3456个配对比较。

## 3. 精确编码边界

下表使用主分析切片：40 bit应用头、Hamming(7,4)。数值是一次发送且不含重传时的精确信道bit，因此不需要抽样置信区间。

| N | 查询族 | 单查询平均 | 多查询包 | occupancy向量 | 4-bit软功率 |
|---:|---|---:|---:|---:|---:|
| 8 | q3 | 280 | 280 | 280 | 322 |
| 8 | q5 | 280 | 294 | 280 | 322 |
| 8 | q7 | 280 | 308 | 280 | 322 |
| 16 | q3 | 280 | 294 | 294 | 378 |
| 16 | q5 | 280 | 308 | 294 | 378 |
| 16 | q7 | 280 | 308 | 294 | 378 |
| 32 | q3 | 280 | 294 | 322 | 490 |
| 32 | q5 | 280 | 308 | 322 | 490 |
| 32 | q7 | 280 | 322 | 322 | 490 |
| 64 | q3 | 280 | 308 | 378 | 714 |
| 64 | q5 | 280 | 322 | 378 | 714 |
| 64 | q7 | 280 | 336 | 378 | 714 |

主要边界如下：

- N = 8时，多查询包相对软功率只降低4.3%—13.0%的名义bit；
- N = 16时，降低18.5%—22.2%；
- N = 32时，降低34.3%—40.0%；
- N = 64时，降低52.9%—56.9%。

因此“信道越多，块索引语义相对逐信道软功率越有优势”的机制得到协议级支持。原因不是算法精度变化，而是索引宽度近似按log₂N增长，软功率载荷按N线性增长。

## 4. 查询数量与occupancy边界

多查询包并非在所有规模都优于N-bit occupancy向量：

- N = 8时，q3与occupancy成本相同，q5和q7分别高5.0%和10.0%；
- N = 16时，q3相同，q5和q7约高4.8%；
- N = 32时，q3和q5分别低8.7%和4.3%，q7相同；
- N = 64时，q3、q5和q7分别低18.5%、14.8%和11.1%。

这说明查询集合不能无限扩张。查询数量增加会使索引和逐渐接近occupancy向量；多查询包的价值取决于“未来状态刷新收益”能否补偿增加的单包长度。

## 5. 兼容头与FEC敏感性

使用152 bit兼容头后，多查询包相对软功率的名义bit降幅变为：

| N | q3 | q5 | q7 |
|---:|---:|---:|---:|
| 8 | 8.1% | 5.4% | 2.7% |
| 16 | 14.6% | 12.2% | 12.2% |
| 32 | 28.6% | 26.5% | 24.5% |
| 64 | 44.6% | 43.1% | 41.5% |

固定头越长，小规模场景的源编码优势越容易被稀释，但N = 32和64时结论仍保持。无FEC、Hamming(7,4)和三重复码改变绝对bit，但没有改变N = 64、q7时的表示排序：

| FEC | 单查询平均 | 多查询包 | occupancy向量 | 4-bit软功率 |
|---|---:|---:|---:|---:|
| 无FEC | 160 | 192 | 216 | 408 |
| Hamming(7,4) | 280 | 336 | 378 | 714 |
| 三重复码 | 480 | 576 | 648 | 1224 |

## 6. 重传后的实际bit与可靠性

在40 bit头和Hamming(7,4)的全部信道条件上，多查询包相对软功率的平均实际bit降幅为：

- N = 8：4.59%—13.78%；
- N = 16：19.24%—23.20%；
- N = 32：35.82%—41.88%；
- N = 64：54.51%—58.82%。

在所有主分析条件中，多查询包相对软功率的最差操作成功率差不低于0。原因是多查询包始终更短。但相对单查询索引，多查询包更长，在低可靠链路下最差成功率差可为负，因此必须依靠事件触发降低发送次数，不能把“单包更长”隐藏在平均bit结论中。

例如N = 64、q7时，多查询事件率低于约0.808，平均链路bit才不高于“每景发送一个单查询索引”。S5.3观察到的多查询上报率约为0.476—0.487，低于该参考边界；但该比较不能替代N = 64真实任务轨迹验证。

总体置信度为 **CAUTION**。协议长度与名义bit是精确可复算结果，但大规模任务性能尚无新测量数据支持。

## 8. 结论与当前创新边界

本实验支持的结论是：

> 多查询块索引语义的载荷随信道规模近似对数增长，而逐信道软功率载荷线性增长。经过真实对齐、CRC、FEC、调制和重传核算后，该结构在N ≥ 32时形成稳定且显著的链路bit优势；查询数量过多时，其优势会向occupancy向量收敛。

本实验还不能证明：

- N = 16、32、64时的regret、CVaR或clean rate保持不变；
- 多查询事件率在更大规模真实频谱轨迹上仍低于盈亏平衡点；
- 64信道结果来自真实64信道测量；
- 当前方法已经通过新的独立Final。
