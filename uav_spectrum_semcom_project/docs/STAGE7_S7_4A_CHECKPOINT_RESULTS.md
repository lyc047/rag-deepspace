## 1. 研究目的

S7.3b表明，频谱任务预测无法可靠发现与频谱变化无关的接收端随机上下文重置。S7.4A因此不再预测重置，而是直接研究协议结构：

> 能否用“码本身份 + 当前任务动作”的周期自包含检查点替代请求—响应心跳，在保持clean的同时降低总通信开销？

这里的“自包含”有严格边界：接收端必须预装匹配的码本目录。检查点不携带完整码本，只携带足以从预装目录中定位码本并恢复当前动作的身份字段。

## 2. 检查点设计

检查点固定身份区共64 bit：

| 字段 | bit |
|---|---:|
| 帧标识 | 8 |
| 协议版本 | 2 |
| 节点编号 | 6 |
| 目录纪元 | 8 |
| 码本库编号 | 8 |
| 码本纪元 | 8 |
| 码本短标签 | 16 |
| 更新纪元 | 8 |

其后附加任务语义码字；escape时再附加精确动作。四种N下普通非escape检查点为66—67 bit，实测含escape的最大长度为75—84 bit。

接收端只有在目录纪元、码本编号和短标签均匹配时才恢复上下文。未知码本、错误目录、错误标签、非法码字或截断帧均被拒绝。该机制的安全主张限于当前包丢失与上下文重置模型；实验没有模拟任意比特翻转，默认下层链路能够检出损坏帧。

## 3. S7.4A-0 帧级可行性

帧级实验只回答“检查点是否比先激活再更新更短”，不能证明系统级收益。

| N | 普通检查点 | 含escape平均bit | escape率 | 相对64-bit激活加紧凑更新的降幅 |
|---:|---:|---:|---:|---:|
| 8 | 66—67 | 67.22 | 5.09% | 37.32% |
| 16 | 67 | 67.58 | 5.31% | 37.20% |
| 32 | 66—67 | 67.72 | 6.84% | 37.17% |
| 64 | 66—67 | 68.24 | 8.71% | 37.02% |

帧级门槛4/4种N通过，因此进入完整协议扫描。

## 4. S7.4A-1 完整协议

比较8种预注册策略：

1. 固定6景、10景和16景请求—响应心跳；
2. 每6、8、10、12和16景发送一次自包含检查点；
3. 检查点替代同景心跳、激活和普通更新，避免重复计费；
4. 检查点通过与普通任务帧相同的丢包、开放环重复、ACK和信念更新路径；
5. 未解析站点在所有策略下使用完全相同的精确动作回退。

主门槛要求同一个检查点间隔至少在3/4种N上满足以下任一路径：

- 路径A：总bit降幅95%区间下界不低于5%，且clean损失区间下界不低于−0.5个百分点；
- 路径B：clean增益95%区间下界不低于1个百分点，且总bit增加不超过5%；
- 两条路径均要求错误码本动作执行次数为0。

## 5. 10景检查点的主结果

| N | 固定10景总bit/景 | 检查点总bit/景 | 配对总bit降幅 | bit降幅95%区间 | clean变化（百分点） | clean变化95%区间 |
|---:|---:|---:|---:|---:|---:|---:|
| 8 | 27.87 | 25.96 | +10.15% | [4.85%，15.10%] | +0.34 | [−0.07，0.82] |
| 16 | 32.83 | 34.63 | −10.41% | [−15.86%，−4.47%] | +0.08 | [−0.20，0.38] |
| 32 | 41.37 | 42.69 | −7.42% | [−13.56%，−1.87%] | +0.06 | [−0.17，0.35] |
| 64 | 39.11 | 37.66 | +7.47% | [2.34%，12.98%] | +0.07 | [−0.27，0.48] |

正的bit降幅表示节省，负值表示增加。10景检查点在N = 8和64上有平均bit收益，但N = 8的区间下界略低于5%，N = 64的区间下界只有2.34%；N = 16和32则稳定增加总bit。因此该策略不具有跨规模一致性。

## 6. 全部间隔的结果与根因

| 检查点间隔 | N = 8 | N = 16 | N = 32 | N = 64 | 通过N数 |
|---:|---:|---:|---:|---:|---:|
| 6景 | 不通过 | 不通过 | 不通过 | 不通过 | 0 |
| 8景 | 不通过 | 不通过 | 不通过 | 不通过 | 0 |
| 10景 | 不通过 | 不通过 | 不通过 | 不通过 | 0 |
| 12景 | 不通过 | 不通过 | 不通过 | 不通过 | 0 |
| 16景 | 不通过 | 不通过 | 不通过 | 不通过 | 0 |

主要机制不是检查点无法恢复上下文，而是成本结构不稳定：

- 固定10景心跳在N = 8、16、32、64上的“心跳 + 恢复”开销分别约为7.89、6.98、5.69和6.74 bit/景；
- 10景检查点自身开销分别约为5.61、10.21、7.76和4.24 bit/景；
- 检查点还会产生正常ACK，ACK总开销约为5.51—5.92 bit/景；
- N = 16和32的检查点发送频率与帧成本高于其省掉的心跳和恢复成本，因而总bit反而上升。

更短间隔能提高clean，却显著增加bit；更长间隔能降低bit，却造成明显clean损失。例如16景检查点相对固定10景平均节省8.87%—25.81% bit，但clean下降2.35—3.51个百分点，超过允许的0.5个百分点。

## 7. 决策结论

S7.4A-1为0/4种N通过，所有策略的错误码本动作执行次数均为0。研究决策为：

1. 不把周期自包含检查点加入冻结主架构；
2. 保留检查点codec、fail-closed测试和负结果，作为“单包压缩不等于系统收益”的协议消融；
3. 不打开内部开发测试集和储备站点；
4. 不按单一N挑选有利间隔；
5. 下一步进入S7.4B“事件更新捎带上下文身份”。

S7.4B不再周期发送完整检查点。它只在解析regret或最大年龄已经触发任务更新时，将普通紧凑更新升级为可从预装目录恢复的更新帧，共用原本就需要的任务ACK。随后扫描更长的稀疏心跳间隔，判断能否减少独立心跳和恢复成本。

## 8. S7.4B预定判定顺序

1. 先统计各N的解析更新率、上下文重置后被事件更新抢先恢复的比例，以及每次升级的附加bit；
2. 若“预期节省的心跳与恢复bit”不足以覆盖升级开销，不运行大规模协议扫描；
3. 若解析上存在空间，比较固定10景基线、固定16景基线，以及12/16/24景心跳加事件自包含更新；
4. 所有策略使用共同随机数、完整ACK与恢复计费；
5. 仍要求同一策略至少在3/4种N通过系统门槛；
6. 若再次失败，停止继续增加有状态协议组件，转向半无状态帧头设计或明确接受固定10景心跳为论文边界。

## 9. 统计解释与11项谬误扫描

总体置信度：CAUTION。结果在已见开发站点上使用预注册策略和分层bootstrap，足以支持分支决策，但不是独立外部验证。

- Simpson悖论：四种N分别报告，并使用站点优先分层bootstrap；不同N方向确实不一致，因此禁止只报告N = 8或64。
- 生态谬误：不把7站点平均结果推断为任一具体无人机链路。
- Berkson偏差：站点经过既有解析流程筛选，不能代表所有无线环境。
- 碰撞变量偏差：未按检查点表现筛选站点或轨迹。
- 基准率忽视：同时报告clean、总bit、ACK、检查点、心跳和恢复开销。
- 均值回归：不适用；没有选择极端故障轨迹作为干预组。
- 幸存者偏差：未删除失败轨迹；未解析站点以相同精确回退计入。
- 多重搜索效应：8种策略与4种N全部报告，没有挑选单一正结果。
- 分叉路径：间隔、门槛、随机种子、轨迹数和bootstrap均在正式运行前注册。
- 相关不等于因果：共同随机数支持对协议策略的受控差异解释，但不能外推到真实无人机故障率。
- 反向因果：不适用于时间有序的受控协议仿真。

覆盖：11/11。
