## 1. 本步要回答的问题

本步不再寻找更好的参数，而是检验在2023排除试点上选出的控制器，能否直接迁移到2022三个固定站点。主要问题为：

1. 在相同clean目标下，任务语义系统是否比逐景精确动作包减少总通信开销；
2. 该优势是否同时存在于实际发送bit和资源等效bit；
3. 结论是否依赖某一个站点或日期；
4. 接收端失步时是否仍保持错误码本动作执行次数为0。

其中：

clean rate＝满足“接收端有可执行动作，且最大查询regret不超过0.2 dB”的场景比例。

资源等效bit＝实际前向bit＋实际反馈bit＋已经预留但未使用的保护容量。

节省率＝100% ×（精确基线bit－语义系统bit）÷精确基线bit。

## 4. 公平比较方法

同一N、同一日期组和同一轨迹中，语义系统与精确动作基线使用完全相同的：

- 接收端重置随机数；
- 任务包丢失随机数；
- 安装包与ACK丢失随机数；
- 延迟ACK和心跳随机数。

因此差异来自协议与表示方法，而不是随机链路恰好更有利。

完整分析采用分层配对bootstrap：

1. 以站点×日期为外层有放回抽样单元；
2. 对每个抽中的日期组，再抽取一条配对链路轨迹；
3. 用各日期组实际进入评测的场景数加权；
4. 重复5,000次，给出95%置信区间。

候选不会在分组结果上重新排序。每个N的粗网格第一名作为主要冻结候选，其余候选只用于稳定性和负结果分析。精确动作基线只依据预注册的matched-clean规则，在固定的1、2、3次发送点中选择达到目标且bit最低的点。
