# 阶段5总计划：查询感知的事件触发频谱语义与状态差分传输

> 建立日期：2026-07-23  
> 当前状态：S5.9 稀疏确认边界实验完成；停止当前开发集上的ACK结构搜索，进入阶段5候选收敛与独立Final注册  
> 研究性质：阶段4 Final 后的新研究周期；不得修改、重跑或覆盖阶段4 Final  
> 工作主线：频谱资源语义，不扩展图像语义，不包装为MIMO或波形级ISAC

## 1. 阶段4之后仍未解决的问题

阶段4已经证明：当信道数 N 和连续需求宽度 D 固定时，发送最优连续块的位置可以作为任务充分语义；其载荷长度低于逐信道软功率，并在 N ≥ 32 时表现出明显的实际发送bit优势。

但现有方法仍有四个边界：

1. 每个场景都发送一次绝对块指示，没有利用最优块随时间保持不变的事实；
2. 只验证了固定 D，不能处理接收端带宽需求变化；
3. 152 bit兼容头部中包含未使用字段，限制了小规模任务的实际通信收益；
4. 最近成功状态只用于丢包回退，没有把“是否值得更新状态”纳入主动决策。

阶段5不再增加频谱检测网络，而是研究：

> 在接收端已经保存最近成功资源决策、任务带宽需求可能变化的条件下，发送端能否根据当前任务损失决定是否上报，并用绝对或差分块索引完成最小必要更新，从而在约束平均regret和尾部风险的同时进一步降低实际发送bit？

## 2. 暂定方法

方法暂称 **QUEST-Spectrum**：

> Query-aware Utility-triggered Event-driven Stateful Spectrum Semantics  
> 查询感知、任务效用触发的有状态频谱语义

名称只用于工程识别；在完成系统文献检索前不宣称名称或整体算法具有唯一性。

### 2.1 查询与连续块代价

对时刻 t 的 N 个信道平均功率 pₜ,ₙ，接收端给出连续带宽需求 Dₜ。候选块数为

Mₜ = N − Dₜ + 1

第 j 个候选块的任务代价为

cₜ^(Dₜ)(j) = (1/Dₜ) · Σ[n = j 至 j + Dₜ − 1] pₜ,ₙ

当前最优决策为

jₜ* = arg min[j] cₜ^(Dₜ)(j)

### 2.2 共享接收状态

发送端根据ACK维护与接收端一致的状态

sₜ(D) = (ĵₜ(D), aₜ(D), eₜ(D))

其中 ĵₜ(D) 是需求 D 最近成功接收的块位置，aₜ(D) 是状态年龄，eₜ(D) 是状态纪元。不同需求分别维护状态，避免将 D = 2 的块位置错误复用于 D = 6。

### 2.3 精确任务价值触发

如果继续使用缓存块，其当前可观测任务损失为

rₜ(reuse) = cₜ^(Dₜ)(ĵₜ₋₁(Dₜ)) − cₜ^(Dₜ)(jₜ*)

该值由发送端当前扫频直接计算，不是用网络预测未知反事实价值，因此不重复阶段4 C2“预发送价值不可辨识”的失败路线。

初始触发规则为

触发变量 uₜ 的取值规则如下：

- uₜ = 1：状态不存在，或状态年龄超过 Aₘₐₓ；
- uₜ = 1：复用损失 rₜ(reuse) > τᵣ；
- uₜ = 0：其余情况。

其中 uₜ = 0 表示静默并沿用接收端状态，uₜ = 1 表示发送更新。

在无传输错误且状态未过期时，静默场景满足

Rₜ ≤ τᵣ

这给出了可解释的逐场景任务损失上界。链路错误造成的额外风险由实际CRC、FEC、有限ARQ和CVaR单独评价。

### 2.4 绝对与差分索引

需要更新时比较两种真实码字长度：

- 绝对索引：⌈log₂ Mₜ⌉ bit；
- 差分索引：对 jₜ* − ĵₜ₋₁ 使用符号位和Elias-gamma幅值编码。

只有差分码字严格更短且共享状态有效时才发送差分，否则发送绝对索引。接收成功后双方更新同一状态纪元；失败时状态不前移。

### 2.5 公平协议

阶段5建立紧凑但可解码的40 bit控制头，包含版本、模式、节点、需求宽度和状态纪元。所有非静默方法使用相同头部。另以152 bit阶段4兼容头作为敏感性分析，分离“事件触发收益”和“协议头压缩收益”。

## 3. 科学假设

### H5.1：事件触发有效性

相对“每景发送紧凑绝对索引”，QUEST-Spectrum在开发验证集上：

- 平均实际发送bit至少降低30%；
- 平均regret差的单侧95%分组bootstrap上界不超过0.02 dB；
- CVaR₀.₉差的单侧95%上界不超过0.05 dB。

### H5.2：差分编码增益

在相同触发时刻和完全相同任务决策下，差分模式相对事件触发绝对索引具有不高于零的实际bit差；如果数字链路的FEC/分包边界使源码长度差不能转化为实际bit，必须报告为“无额外链路收益”。

### H5.3：动态需求可行性

在 D ∈ {2, 4, 6} 的冻结需求序列上，按需求维护独立状态，相对逐信道4-bit软功率在保持任务风险门槛的同时降低实际bit。动态需求结果只作为阶段5开发结论，必须在新数据上独立确认。

## 5. 第一轮实验设计

### 5.1 方法

1. `soft_power_fixed4_always`：每景发送逐信道4-bit功率；
2. `onehot_always`：每景发送最优块独热指示；
3. `absolute_index_always`：每景发送紧凑绝对索引；
4. `periodic_absolute`：固定周期更新的事件通信基线；
5. `event_absolute`：按精确reuse regret触发，更新时发送绝对索引；
6. `event_delta`：相同触发规则，绝对/差分码长自适应。

所有方法在丢包后使用同一带最大年龄的最近成功状态规则。

### 5.2 冻结候选

- N = 8；
- 固定任务 D = 4 先完成机制验证；
- 动态任务使用 D ∈ {2, 4, 6}；
- τᵣ ∈ {0, 0.02, 0.05, 0.1, 0.2, 0.5, 1.0} dB；
- Aₘₐₓ ∈ {30, 60, 120} min；
- 紧凑头40 bit，兼容头152 bit；
- AWGN、Rayleigh、Rician；
- Eᵦ/N₀ ∈ {0, 3, 6, 9} dB；
- 每条件10次共同随机数重复；
- 按“站点×本地小时”做10,000次配对bootstrap。

先在calibration按H5.1约束筛选，合格候选中选择平均实际bit最少者；并列时依次比较CVaR、平均regret、更新率和阈值大小。选择规则冻结后才运行validation。

## 6. 消融与失效分析

必须完成：

1. 去掉年龄上限；
2. 将task-regret触发替换为“最优块是否改变”；
3. 将差分编码替换为始终绝对编码；
4. 40/152 bit头部敏感性；
5. 固定与动态需求；
6. 平稳时段与突变时段分组；
7. 不同站点分别报告；
8. 链路全失败区、过渡区和高可靠区分别解释。

特别检查：

- 长时间静默导致的状态陈旧；
- ACK状态不同步；
- 更新包失败后的连续错误；
- 阈值只在慢变固定站点上有效；
- 低源码长度未跨越FEC边界；
- 动态需求切换导致缓存稀疏。

## 7. 机器学习的进入条件

第一轮不使用机器学习。只有同时出现以下事实时才引入轻量学习：

1. 精确regret触发在动态或部分观测条件下不可直接计算；
2. calibration显示固定阈值不能跨站点或跨需求保持风险约束；
3. 可定义部署时真实可获得的输入，且不存在标签泄漏；
4. 新模型必须优于解析阈值、逻辑回归、树模型等简单基线。

优先顺序为逻辑回归/梯度提升树、上下文多臂老虎机，最后才考虑深度强化学习。模型复杂度本身不算创新。

## 10. 当前决策记录

### D5-001

- 决策：阶段5优先研究事件触发与状态差分频谱语义；
- 依据：阶段4已经验证固定任务最优块语义，下一缺口是时间冗余、动态需求和协议开销；
- 不采用：继续堆叠检测网络、图像语义、MIMO标签、直接上DQN；
- 数据权限：仅阶段4开发缓存和新数据，禁止读取阶段4 C1-v4 Final；
- 回退：如果事件触发不能同时满足bit和风险门槛，则保留紧凑绝对索引作为协议扩展负结果。

### D5-002

- 决策：固定需求候选冻结为 τᵣ = 0.2 dB、Aₘₐₓ = 120 min；
- calibration依据：相对每景绝对索引，实际bit降低45.96%，平均regret单侧95%上界0.00593 dB，CVaR差上界−0.01410 dB；
- validation结果：实际bit降低45.95%，平均regret差0.00169 dB、单侧95%上界0.00711 dB，CVaR差上界0.00922 dB，满足H5.1开发门槛；
- 差分结论：4.87%的场景使用差分模式，但1 bit源码差未跨越当前FEC/分包边界，实际bit与事件触发绝对索引完全相同；H5.2只能记为“任务不变、链路bit无额外收益”；
- 对照结论：60分钟固定周期方法bit降低46.47%，但平均regret增加0.13865 dB、CVaR增加0.48663 dB，证明不能用固定少发替代任务价值触发；
- 证据：`docs/STAGE5_S5_1_FIXED_DEMAND_RESULTS.md`；
- 下一步：保持固定需求结果不再调参，使用开发数据构造冻结的 D ∈ {2, 4, 6} 查询序列，进入S5.2。

### D5-003

- 决策：S5.1的0.2 dB/120分钟参数在S5.2中保持不变，不针对动态查询重新搜索；
- Markov需求：实际bit降低39.36%，平均regret上界0.01621 dB、CVaR上界0.02146 dB，通过描述性门槛；
- 每景周期切换需求：实际bit只降低26.33%，平均regret上界0.02503 dB、CVaR上界0.11878 dB，门槛失败；
- 机制判断：按需求独立缓存依赖查询持续性；快速切换使每个需求状态的有效刷新间隔增加；
- 负结果处置：不通过重新搜索更宽松阈值掩盖失败；
- 下一算法：一次更新同时发送 D ∈ {2, 4, 6} 的最优块索引，利用同一功率扫频构造“多查询任务充分语义包”，使一个成功包同步刷新全部查询状态；
- 证据：`docs/STAGE5_S5_2_DYNAMIC_QUERY_RESULTS.md`。

### D5-004

- 决策：采用8-bit多查询块索引包作为S5.3候选架构；触发阈值和年龄仍保持0.2 dB/120分钟；
- 周期查询：相对每景单查询绝对索引，实际bit降低48.29%，平均regret差−0.00610 dB、上界0.00410 dB，CVaR差上界−0.05046 dB；
- Markov查询：实际bit降低49.50%，平均regret差−0.00606 dB、上界0.00656 dB，CVaR差上界−0.04039 dB；
- 相对S5.2按查询事件方法：周期查询继续降低29.64% bit，Markov查询降低16.12% bit，且两种序列的平均与CVaR上界均严格低于0；
- 机制解释：成功的多查询包把同一时刻的三个任务决策写入接收端状态，因此查询切换后的回退状态更近，减少了状态缺失和陈旧引发的重复发送及尾部损失；
- 协议边界：48-bit多查询应用报文与42—43 bit单查询报文在当前链路中处于相同FEC/分包区间；该“无额外单包实际bit”现象不能外推到其他协议；
- 证据：`docs/STAGE5_S5_3_QUERY_BUNDLE_RESULTS.md`；
- 下一步：在 N ∈ {16, 32, 64}、更大的需求集合、不同固定头长度和突变频谱序列上验证包长—刷新收益边界，再决定是否需要学习型查询预测。

### D5-005

- 决策：保留40 bit紧凑头和多查询事件包作为下一轮任务风险压力测试的主候选，同时保留occupancy向量作为必要强基线；
- 规模结论：40 bit头、Hamming(7,4)下，多查询包相对4-bit软功率的名义bit降幅由N = 8时的4.3%—13.0%扩大到N = 64时的52.9%—56.9%；
- 查询边界：N = 8和16时，q5/q7多查询包可能比occupancy向量长；N = 64时，q3/q5/q7分别比occupancy向量低18.5%、14.8%和11.1%；
- 头长边界：152 bit兼容头削弱小规模收益，但N = 64时相对软功率仍降低41.5%—44.6%；
- FEC结论：无FEC、Hamming(7,4)和三重复码改变绝对bit，但没有改变N = 64、q7时“多查询包 < occupancy向量 < 软功率”的排序；
- 证据：`docs/STAGE5_S5_4_SCALE_CODEC_BOUNDARY_RESULTS.md`；
- 限制：未加载或伪造N > 8的测量频谱，因此当前只证明协议与仿真回传链路边界，不能声称大规模任务regret已验证；
- 下一步：进入S5.5突变频谱、ACK失配、状态陈旧和连续丢包压力测试，并以regret、CVaR、实际bit和事件率盈亏平衡为联合判据。

### D5-006

- 决策：频谱压力测试不触发阈值重调；固定多查询事件包继续进入状态一致性实验；

### D5-007

- 决策：保留8-bit纪元旧ACK保护；当前“一次未确认即持续绝对刷新”不冻结为最终协议；
- 重复ACK：无ACK丢失、10%重复ACK时，纪元保护将状态分叉率由5.7%降至0；
- ACK丢失：纯纪元保护不能解决未收到确认的问题；
- 自愈收益：5%—20% ACK丢失下，立即自愈相对天真ACK降低平均regret 0.00643—0.01844 dB，额外bit为1.70%—5.61%；
- 门槛结果：严格平均和CVaR改善门槛仅4/8条件通过；无故障时存在18.9%的强制恢复率和4.02%的额外bit；
- 证据：`docs/STAGE5_S5_6_ACK_STATE_RECOVERY_RESULTS.md`；
- 限制：ACK故障为仿真注入，不是真实无人机回传测量；
- 下一步：开发“两次连续未确认或接近年龄上限才强制刷新”的迟滞恢复，目标是保留高故障收益并消除低故障过度发送。

### D5-008

- 决策：两次未确认迟滞及其80%年龄保护版本均不冻结；
- bit结果：相对立即恢复，两种迟滞分别降低3.24%—4.73%和2.52%—3.93%的实际bit；
- 风险结果：两种方法都只在ACK丢失为0的2/8条件通过；ACK丢失达到5%后平均或CVaR非劣门槛全部失败；
- 极端边界：20% ACK丢失和10%重复ACK下，两次迟滞虽节省4.32% bit，但CVaR增加0.07144 dB，差值上界0.16991 dB；
- 机制判断：状态年龄和未确认次数不能及时表征突变频谱下的接收状态分叉风险；
- 证据：`docs/STAGE5_S5_7_ACK_HYSTERESIS_RESULTS.md`；
- 下一步：停止调整迟滞次数，改为接收端重复最新累计ACK，使发送端先用低成本控制反馈恢复状态知识，累计ACK超时后才重发语义数据。

### D5-009

- 决策：固定重复一次和两次累计ACK均不冻结，并停止搜索更多固定重复次数；
- 公平核算：24-bit累计确认经16-bit包头、16-bit CRC和Hamming(7,4)编码后，每个反馈帧实际消耗98 bit；首次、重复和延迟重复ACK均计入总bit；
- 数据层结果：相对立即语义恢复，一次重复降低0%—6.64%的语义数据bit，两次重复降低2.67%—9.34%；
- 系统层结果：控制成本抵消全部数据节省，一次重复使总bit增加4.54%—12.08%，两次重复使总bit增加8.81%—17.51%，两者均只通过0/8联合门槛；
- 风险结果：一次重复的平均regret与CVaR非劣门槛通过8/8；两次重复通过7/8，说明失败主因是反馈资源成本，而不是状态恢复完全无效；
- 状态结果：跨条件平均状态分叉率由立即恢复的4.21%降至2.82%和2.75%，但这项可靠性收益不足以补偿固定反馈；
- 盈亏边界：在20% ACK丢失下，单帧累计ACK需约降至45—55 bit才可能仅靠压缩达到总bit盈亏平衡；低故障区要求更苛刻；
- 证据：`docs/STAGE5_S5_8_CUMULATIVE_ACK_RESULTS.md`；
- 下一步：进入S5.9按需稀疏确认，使用发送端确认请求和反向业务捎带累计纪元，目标是减少独立反馈帧次数；若仍不能降低总bit，则结束ACK结构优化并保留立即语义恢复。

### D5-010
