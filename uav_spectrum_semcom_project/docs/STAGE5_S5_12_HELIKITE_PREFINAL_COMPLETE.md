## 3. 2023 空中试点适配

### 3.1 数据结构

试点包包含：

- 364 对功率扫频 SigMF 文件；
- 每次扫频包含 98,868 个频率值和 98,868 个 dBm 功率值；
- 频率覆盖约 87.16–6019.18 MHz；
- GPS 文件包含经度、纬度、高度和时间戳。

研究任务固定为 3550–3700 MHz。该频段是外部定义的 CBRS 共享频段，不是根据试点算法结果挑选的“有利频段”。分析频段内每个扫频有 2500 个频点，频率分辨率约 0.06006 MHz。

### 3.2 质量控制结果

| 检查项 | 结果 |
|---|---|
| 扫频数量 | 364/364 |
| SigMF SHA-512 | 全部通过 |
| 频率网格一致性 | 通过 |
| 分析频段频点数 | 2500/帧 |
| 观测功率范围 | −135.69 至 −109.06 dBm |
| 扫频间隔 | 15–16 s |
| 飞行高度范围 | 3.72–134.92 m |
| 15 分钟时间簇 | 7 个 |
| GPS 最近邻最大残差 | 0.501 s |

GPS 原始 Unix 时间与扫频文件名时钟存在稳定的 13 小时偏移。适配器没有自由拟合连续偏移，而是冻结为“在 −14 至 +14 小时的整数小时集合中，选择中位绝对时间残差最小的校正量”。该规则只使用时间戳，不使用频谱值或方法输出；试点得到 +13 小时校正。

## 4. N = 8/16/32/64 空中实测规模实验

### 4.1 固定语义表示

对每个 N，需求集合固定为：

`D ∈ {N/4, N/2, 3N/4}`

4-bit 软功率每次更新的应用层长度为：

`B_soft = H + 4N`

多查询块索引包的应用层长度为：

`B_bundle = H + Σ ceil(log₂(N − D + 1))`

其中 H = 40 bit，求和覆盖三个冻结需求。多查询包发送同一扫频下三个需求的最优连续块起点，因此成功解码时与发送端任务最优决策一致。

### 4.2 主要结果

| N | 查询包应用层 bit 降幅 | 计入 Hamming(7,4) 后名义 bit 降幅 | 软功率平均 regret | 事件包平均 regret | 事件包最大 regret |
|---:|---:|---:|---:|---:|---:|
| 8 | 33.33% | 13.04% | 0.000052 dB | 0.00540 dB | 0.15979 dB |
| 16 | 50.96% | 22.22% | 0.000105 dB | 0.00834 dB | 0.18642 dB |
| 32 | 67.86% | 40.00% | 0.000268 dB | 0.00889 dB | 0.18701 dB |
| 64 | 80.74% | 56.86% | 0.000337 dB | 0.00914 dB | 0.18667 dB |

四个描述性检查全部通过：

- 始终发送查询包的成功解码 regret 为 0；
- 事件查询包的逐场景 regret 不超过冻结的 0.2 dB；
- 所有 N 下查询包应用层长度均低于 4-bit 软功率；
- 查询包相对软功率的 bit 优势从 N = 8 到 N = 64 单调扩大。

事件包在该 90 分钟空中轨迹上的发送率约为 3.57%–4.12%，名义传输 bit 相对始终发送软功率降低约 96.8%–98.2%。该数值高度依赖试点轨迹的时间相关性和仅 7 个时间簇，只能作为机制说明，不能替代三批外部 Final 的聚类统计。

## 5. 统一外部 Final 协议

### 5.1 冻结方法

主比较固定为：

- 4-bit occupancy；
- 4-bit 软功率；
- 当前查询绝对块索引；
- 始终发送多查询块索引包；
- 0.2 dB/120 分钟事件触发多查询包。

ACK 丢失、重复 ACK 和状态信念恢复保留为受控注入的次要鲁棒性证据。三批外部数据没有真实回传链路或 ACK 轨迹，因此不能把该部分写成“实测 ACK 鲁棒性”。

### 5.2 200 场景目录

只根据压缩包成员名中的时间戳完成场景选择：

| 活动 | 可发现扫频对 | 选定场景 |
|---|---:|---:|
| Packapalooza 2024 | 1437 | 67 |
| Lake Wheeler 2024 | 1524 | 67 |
| Packapalooza 2025 | 1454 | 66 |
| 合计 | 4415 | 200 |

选择规则为：每个活动先按时间排序并执行至少 5 分钟的贪心稀疏化，再用确定性等间隔索引覆盖全时段。200 个场景形成 79 个“活动 × 15 分钟”统计簇。所有方法必须使用完全相同的目录。

建立目录时：

- 未读取 SigMF 元数据正文；
- 未读取功率值；
- 未运行任何候选方法；
- 未根据 regret、bit 或成功率筛选场景。

代码快照冻结了 76 个可执行或配置文件，快照标识为：

`cbe82c100e79a5d295ded06a821805587a76b1294cb8d94acfe8917cf8d586a6`
