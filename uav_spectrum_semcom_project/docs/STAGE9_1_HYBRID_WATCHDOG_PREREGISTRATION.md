## 1. 研究问题

阶段9已经证明启动事件恢复在三类软件故障中优于固定10景心跳，但其前提是接收端启动状态发送器能够工作。阶段9.1研究：

> 当启动状态发送器自身失效时，加入低频安全看门狗能否恢复系统活性，同时在正常条件下保留启动事件相对固定10景心跳的 clean–bit 优势？

## 2. 候选协议

候选 S9-HBW30-v1 保留 S9-BER-v2 的启动事件作为主要恢复路径，并加入30景静默看门狗作为后备路径。每次收到有效更新 ACK、恢复 ACK 或上下文响应后，重新计算静默时间。

30景是执行前冻结的主设计点，60景只用于说明恢复时延与开销的敏感性，不得根据结果把60景改为主候选。任务码本、regret、escape、ACK 和 fail-closed 规则均不改变。

## 3. 新故障类型

除既有前向、反馈、突发丢包、热重启和冷重启外，新增“每次启动时启动状态发送器失效”。失效后，该次进程生命周期内不产生启动状态；普通任务更新和看门狗仍可工作。

该故障用于检验协议的单点失效，不表示真实无人机具有相同故障率。

## 4. 双重验收

正常启动事件条件下，S9-HBW30-v1 相对 fixed10 必须在两类故障中同时满足：

- clean 差值95%置信区间下限不低于 −0.5 个百分点；
- 相对 bit 节省95%置信区间下限高于5%。

启动发送器退化或完全失效时，S9-HBW30-v1 相对纯 boot_event 必须在两类故障中同时满足：

- clean 提升95%置信区间下限高于1个百分点；
- 平均 bit 增幅不超过20%。

所有条件错误上下文动作执行次数必须为0，30景看门狗的恢复时延95分位数不得劣于60景看门狗。

## 5. 真实进程一致性

除大样本状态模拟外，必须启动真实接收端子进程并执行：

- 冷启动和完整安装；
- 普通更新；
- 丢弃更新；
- 延迟旧更新拒绝；
- 保留目录的进程 kill/restart；
- 使用预安装目录恢复；
- 删除目录后的完整重装。

真实进程测试用于验证状态生命周期和安全拒绝，不用于估计真实故障概率。
