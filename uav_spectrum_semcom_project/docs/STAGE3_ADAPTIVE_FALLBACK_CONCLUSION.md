# 阶段 3 后续完善：ACK 候补与风险回退

## 改进目标

上一版固定选择两个高价值节点，正常情况下可以减少约 55% 发送 bit，但当关键节点
掉线或报告陈旧时性能显著恶化。本轮增加两级回退：首先根据 ACK/解码结果补发候补
节点；其次在失败、陈旧或报告冲突时扩大仲裁节点数量。所有补发包均计入实际 bit。

## 冻结协议

- 验证数据：val 源偏移 3000，共 80 个时序场景、3 次重复；
- 正式测试：test 源偏移 4000，共 200 个新场景、5 次重复；
- 初始调度：价值/bit排名最高的两个节点；
- 冻结策略：目标获得3份报告，失败时继续尝试第四节点；
- 融合：3份以上使用质量权重及一致性裁剪，否则使用保守等权平均；
- 调度输入不包含当前测试真值。

验证集最终把分歧阈值选为0，说明两份报告不足以可靠判断异常，当前更稳妥的策略是
正常情况下直接保留三节点仲裁，而不是等待检测到冲突后再扩容。

## 正式结果

| 条件 | 全节点平均 regret / bit | 自适应回退 regret / bit | 结果 |
|---|---:|---:|---|
| 正常四节点 | 0.013133 / 3427.9 | 0.012965 / 2397.8 | 节省30.0%，差异不显著 |
| 最佳节点失效 | 0.015039 / 2548.9 | 0.015072 / 2548.9 | 自动全节点回退，基本等价 |
| 组合异常 | 0.016741 / 2736.1 | 0.016711 / 2736.1 | 自动全节点回退，基本等价 |
| 高置信错误 | 0.016423 / 3427.9 | 0.016530 / 2397.8 | 节省30.0%，差异不显著 |
| 高SNR节点陈旧 | 0.016475 / 3438.8 | 0.016281 / 2408.8 | 节省30.0%，差异不显著 |

正常条件下，自适应方法相对全节点平均的配对 regret 差为 -0.000168，95% CI
[-0.000401, 0.000065]。关键节点失效和组合异常下的差异也均不显著，说明回退机制
解决了固定两节点方案最明显的鲁棒性问题。

## 客观结论

本轮可以支持一个有限但较扎实的结论：在当前半合成场景中，三节点节流配合ACK候补
能够在正常条件下降低约30%通信开销，并在关键节点失效时恢复到全节点开销和相近
任务性能。

鲁棒质量融合相对相同调度下的等权平均仍没有显著优势，因此有效改进主要来自节点
调度与失败回退，而不是融合权重。该结论属于任务通信效率与失效恢复证据，尚不能
替代同源I/Q回放或同步多接收机所需的真实多无人机空间协同证据。
