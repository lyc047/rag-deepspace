# 阶段 3 改进方法结论：价值/bit 节点选择与鲁棒融合

## 方法

改进方法先利用验证集冻结的节点历史任务正确率、上报链路可靠性、信息年龄和预期
发送 bit，为每个节点计算预期价值/bit，只调度少量节点上传频谱语义。接收端再使用
校准置信度、质量权重、跨节点一致性和权重裁剪进行融合。调度阶段不读取当前频谱
占用内容，也不使用测试真值。

验证集从 1/2/3/4 个节点及多组一致性参数中选择了 2 节点策略。正式测试使用从未
参与诊断的 test 源偏移 3000，共 200 个时序场景、7 种条件和 5 次重复。

## 结果

| 条件 | 全节点平均 regret / bit | 改进方法 regret / bit | 判断 |
|---|---:|---:|---|
| 正常四节点 | 0.009366 / 3297.9 | 0.009642 / 1486.8 | bit 减少 54.9%，regret 无显著差异 |
| 最佳节点失效 | 0.012116 / 2486.9 | 0.013057 / 675.8 | regret 显著变差 |
| 高置信错误 | 0.011991 / 3297.9 | 0.012354 / 1486.8 | 差异区间跨 0 |
| 高 SNR 节点陈旧 | 0.010771 / 3294.9 | 0.012231 / 1393.5 | regret 显著变差 |

正常场景中，改进方法相对全节点平均的配对 regret 差为 +0.000276，95% CI
[-0.000342, 0.000894]。因此可以报告明显的 bit 节省现象，但不能声称已经得到
严格统计非劣。

## 机制消融

在相同已选节点和完全相同发送 bit 下，鲁棒质量权重相对选中节点等权平均的 regret
差异均不显著。原因是验证集最终只选择两个节点，而基于中位数的异常一致性门控至少
需要三个报告才能可靠判断谁是离群节点。因此本轮性能主要来自节点选择，而不是异常
鲁棒融合。

## 结论边界

价值/bit 节点选择已经表现出降低通信开销的潜力，但固定两节点策略在关键节点掉线或
过期时缺少回退能力。下一步需要 ACK 触发的候补节点调度、至少三节点的异常仲裁以及
风险升高时自动恢复全节点上报。当前结果仍是半合成证据，只能支持通信效率研究，不能
证明真实多无人机空间协同增益。
