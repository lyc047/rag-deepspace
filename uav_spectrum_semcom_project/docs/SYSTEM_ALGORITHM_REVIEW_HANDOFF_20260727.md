## 摘要

本项目研究受限上报链路下的连续频谱块选择。发送端从真实宽带功率扫频中构造N维信道功率向量，针对一个或多个连续带宽需求D计算候选块平均功率，并以任务regret衡量接收端动作相对当前最优动作的损失。算法经历三次主要升级：阶段4将逐信道occupancy或软功率上报改为最优块任务语义；阶段5利用接收端缓存状态、精确复用regret和任务查询集合进行事件触发及多查询刷新；阶段6进一步把多个在任务上近似等价的频谱状态压缩到同一离散码字，并加入版本化码本、精确动作逃逸、累计ACK信念恢复、固定静默心跳和轻量一步风险排序。当前冻结系统的核心是“任务等价编码与可靠上下文闭环联合设计”，机器学习仅用于有限重复保护容量的排序，不能直接选择频谱动作，也不能压制硬风险触发。阶段6在排除型固定站点开发缓存上通过14项验收和323项回归测试，但尚未证明跨活动泛化、同clean rate下端到端bit优势、实测ACK鲁棒性、移动无人机多节点协作或MIMO物理层有效性。

## 2. 系统的准确定位

### 2.1 研究对象

系统解决的是以下通信控制问题：

- 发送端可观测当前宽带频谱功率；
- 接收端需要从N个候选信道中选择连续D个信道；
- 发送端到接收端的控制链路存在包长、丢包、ACK丢失和上下文重置；
- 目标不是重构完整功率谱，而是用尽可能少的通信开销维持资源选择任务性能。

### 2.2 推荐术语

最稳妥的名称是“离散任务导向语义通信”或“任务导向频谱语义信令”。系统把与任务结果相关的动作等价类作为待传语义，而不是传输完整逐信道观测。

该系统与主流图像、语音或视频语义通信存在明显区别。它没有使用深度网络提取高维潜在语义，也没有通过JSCC联合映射连续特征与信道符号。当前“语义”是可解释的离散任务变量，包括最优块位置、任务等价码字和接收端上下文状态。因此，论文中不宜笼统声称“提出了通用语义通信系统”，应限定为频谱资源控制场景下的离散任务导向语义信令。

### 2.3 不属于什么系统

- 不是MIMO系统：当前模型没有多天线信道矩阵、波束赋形、空分复用或分集接收。
- 不是波形级通感一体化：频谱测量与资源控制有关，但没有共同波形、联合感知通信波束或感知互信息设计。
- 不是JSCC：源语义形成和数字链路编码分开实现。
- 不是已验证的多无人机协同感知系统：阶段6开发数据为单条helikite轨迹，故障为受控注入。
- 不是频谱预测直接控制器：预测器只给重复保护机会排序。

## 5. 任务模型与评价量

### 5.1 连续频谱块

给定N个离散信道和连续需求D，可选块起点数量为：

`M = N − D + 1`

第j个候选块覆盖信道j到j + D − 1，其平均功率代价为：

`c(x, D, j) = [pⱼ + pⱼ₊₁ + … + pⱼ₊D₋₁] ÷ D`

功率越低，资源块越优。当前最优起点为：

`j* = arg min[j] c(x, D, j)`

### 5.2 Regret

若接收端执行动作a，则任务损失定义为：

`R(x, D, a) = c(x, D, a) − min[a′] c(x, D, a′)`

R = 0表示动作达到当前最优。R > 0表示所选块的平均功率比最优块高R dB。

对多个查询q₁、q₂、…、qQ，系统以最坏查询损失判断一个联合动作：

`Rₘₐₓ(x, a) = max[q] R(x, q, a_q)`

阶段6冻结容差为ε = 0.2 dB。只要Rₘₐₓ ≤ ε，该动作元组即被视为任务安全。

### 5.3 Clean、可用率与尾部风险

- `clean rate`：有效场景中满足冻结任务约束的比例；阶段6闭环将不可用和超阈值场景均视为不clean。
- `availability rate`：接收端是否拥有可执行且上下文一致的动作状态。
- `CVaR₀.₉(R)`：最差10%场景的平均regret。阶段6将不可用场景记为10 dB掉线惩罚，因此当不可用率超过10%时，CVaR会被10 dB封顶。
- `actual/application bits`：阶段4数字链路报告含分包、CRC、FEC和重传的实际发送bit；阶段6消融主要报告应用层前向与ACK总bit，必须避免跨阶段混用。

## 6. 阶段4算法：任务充分块语义

### 6.1 表示方法

阶段4固定N = 8、D = 4，共5个候选连续块。发送端从当前8维功率向量计算五个候选块的平均功率，只发送最优块位置。

原C1-v4表示为5维1-bit独热指示：

- 最优候选位置编码为0；
- 其余位置编码为1；
- 加入152-bit兼容头后应用层总长度为157 bit。

occupancy基线逐信道发送4-bit占用程度，应用层总长度为184 bit。软功率基线逐信道发送4-bit或8-bit量化功率。

### 6.2 丢包回退

无状态基线在整包失败后选择固定块0。完整V4维护同站点、同链路条件下最近成功块：

- 若最近成功状态年龄不超过60分钟，复用最近成功块；
- 否则选择块0；
- 该机制不增加发送bit。

60分钟不是开发集上的性能最优阈值，而是限制无限陈旧复用的安全边界。

### 6.3 阶段4确认性结果

| 方法 | 应用层bit | 平均regret/dB | CVaR₀.₉/dB | 平均实际发送bit | 帧成功率 |
|---|---:|---:|---:|---:|---:|
| occupancy无状态 | 184 | 0.708167 | 2.402559 | 755.448 | 67.530% |
| 最优块指示无状态 | 157 | 0.302646 | 0.944649 | 691.206 | 68.232% |
| 最优块指示+60分钟保护 | 157 | 0.217700 | 0.642915 | 691.206 | 68.232% |

相对occupancy，最优块指示无状态使平均regret降低57.26%、CVaR降低60.68%、实际发送bit降低8.50%。在相同157-bit报文和相同包成功轨迹下，60分钟保护相对无状态又使平均regret降低28.07%、CVaR降低31.94%。H1和H2按预注册固定顺序通过。

### 6.4 补充基线给出的更严格解释

开发集补充比较显示，最优块指示相对4-bit软功率的平均regret和CVaR只再改善约2.42%，实际bit降低8.46%。因此，阶段4的主要价值不是比软功率获得数量级性能提升，而是把近似相同的资源选择性能压缩为更短的任务表示。

当N扩展到32和64时，逐信道软功率长度按4N增长，而任务索引按候选数或其对数增长。在D/N = 0.5时，独热表示相对4-bit软功率的实际bit降幅由N = 8的8.49%增至N = 64的43.11%。这一规模结果属于Final后的开发证据，不是阶段4确认性Final的一部分。

## 7. 阶段5算法：查询感知事件触发与状态更新

### 7.1 接收端查询状态

针对每个需求D，发送端根据ACK维护接收端状态：

`sₜ(D) = [ĵₜ(D), aₜ(D), eₜ(D)]`

其中ĵ是最近成功块起点，a是状态年龄，e是8-bit状态纪元。不同D分别维护状态，禁止把D = 2的动作直接用于D = 6。

### 7.2 精确复用损失触发

发送端在当前功率谱已知时，直接计算继续复用缓存块的损失：

`rₜ,reuse = c(xₜ, Dₜ, ĵₜ₋₁) − c(xₜ, Dₜ, jₜ*)`

触发规则为：

1. 没有有效状态时发送；
2. 状态年龄超过Aₘₐₓ时发送；
3. rₜ,reuse > τᵣ时发送；
4. 其余情况静默，并让接收端继续使用缓存动作。

阶段5开发冻结τᵣ = 0.2 dB、Aₘₐₓ = 120分钟。静默不是“什么也不表达”，而是隐式表达“缓存动作仍满足任务阈值”。

### 7.3 绝对索引与差分索引

绝对索引所需payload为：

`B_abs = ceil[log₂(M)]`

差分模式对jₜ* − ĵₜ₋₁使用符号位和Elias-gamma幅值码。只有差分码字严格更短且共享状态有效时才使用差分。

N = 8、D = 4时，差分只在4.87%的场景使用，源码最多节省1 bit，未跨越CRC/FEC/分包边界，因此实际bit收益为0。该负结果已保留，差分编码没有进入阶段6核心贡献。

### 7.4 多查询机会式刷新

动态需求D ∈ {2, 4, 6}逐景周期切换时，单查询事件更新没有通过风险门槛。阶段5因此改为：一旦需要发送，就使用同一功率扫频同时计算三个需求的最优块，并在一个查询包中发送三个索引。成功后一次刷新全部查询状态。

N = 8时，三个精确索引payload合计8 bit，另加40-bit紧凑头。开发演练中：

| 查询序列 | 实际bit/景 | 平均regret/dB | CVaR₀.₉/dB | 发送率 | 相对逐景绝对索引bit降幅 |
|---|---:|---:|---:|---:|---:|
| cyclic | 203.920 | 0.15952 | 0.57609 | 48.72% | 48.29% |
| Markov | 199.293 | 0.15372 | 0.54124 | 47.64% | 49.50% |

多查询包相对早期单查询事件方法又分别降低29.64%和16.12%的实际bit。该结论来自已见开发数据上的模拟演练，不是阶段5独立Final。

### 7.5 ACK研究的边界

阶段5比较了立即恢复、累计ACK重复、按需请求和捎带确认。固定重复累计ACK能减少状态分叉，但单个反馈帧经保护后约98 bit，导致总bit在全部条件中增加。捎带8-bit纪元只在约20%高控制擦除条件下实现1.13%—1.72%的总bit降低。

这些负结果促使阶段6不把ACK视为免费，也不采用固定高频重复确认，而是维护接收端上下文可能状态集合并采用保守恢复。

## 8. 阶段6核心算法：解析型任务等价码本

### 8.1 任务状态

每个频谱场景对每个查询生成：

- 所有候选块代价；
- 精确最优起点；
- 最优代价；
- ε可接受动作集合；
- 最优与次优代价间隔。

一个动作a属于查询q的ε可接受集合，当且仅当：

`R(x, q, a) ≤ ε`

### 8.2 候选动作元组

开发集中每个场景都有一个多查询精确最优动作元组，例如：

`a*(x) = [j*₍0.25N₎, j*₍0.50N₎, j*₍0.75N₎]`

算法收集开发集中出现过的不同精确最优元组作为候选码字动作。每个码字解码为一个固定动作元组。

### 8.3 贪心覆盖

对候选动作元组a，定义覆盖集合：

`C(a) = {x：max[q] R(x, q, a_q) ≤ ε}`

码本按以下固定顺序贪心构造：

1. 选择能覆盖最多未覆盖开发状态的动作元组；
2. 若覆盖数相同，选择新覆盖状态上平均最坏regret更低者；
3. 若仍相同，按动作元组字典序选择；
4. 移除已覆盖状态并继续，直到全部覆盖或达到码字上限。

该过程是解析型集合覆盖启发式，不是端到端神经码本学习。确定性并列规则保证同一输入产生相同码本。

### 8.4 在线编码

给定当前任务状态，编码器检查每个码字：

1. 计算该码字动作在所有查询上的regret；
2. 保留最大regret不超过ε的可行码字；
3. 选择最大regret最小者；
4. 若并列，选择码字编号更小者。

若没有安全码字，发送保留的escape符号并附加所有查询的精确动作索引。这个逃逸机制保证码本覆盖不足时不会为了节省bit违反硬任务约束。

### 8.5 当前开发码本

在N = 8、16、32、64和需求比例0.25、0.50、0.75上，冻结开发结果均得到3个码字，因此连同一个escape符号，固定码字符号宽度为2 bit。开发评估精确回退率为0，但escape仍必须保留以处理外部分布偏移。

| N | 三查询精确索引payload | 联合码字payload | 开发回退率 | 最大观测regret |
|---:|---:|---:|---:|---:|
| 8 | 8 bit | 2 bit | 0% | 0.145 dB |
| 16 | 11 bit | 2 bit | 0% | 0.145 dB |
| 32 | 14 bit | 2 bit | 0% | 0.163 dB |
| 64 | 17 bit | 2 bit | 0% | 0.163 dB |

2-bit payload相对精确索引bundle降低75.0%—88.2%。这只是语义payload，不包括48-bit头部、安装、心跳、ACK和恢复开销，不能代替端到端bit结论。

## 9. 版本化码流与码本身份

### 9.1 任务更新帧

任务更新至少包含：

| 字段 | 长度 | 作用 |
|---|---:|---|
| magic | 8 bit | 帧类型识别 |
| version | 3 bit | 协议版本 |
| message type | 2 bit | 消息类型 |
| node ID | 8 bit | 节点标识 |
| query count | 3 bit | 查询模式 |
| codebook epoch | 8 bit | 码本版本 |
| codebook tag | 16 bit | SHA-256前缀标签 |
| codeword symbol | 2 bit，当前 | 三个码字和一个escape |
| exact actions | 条件出现 | 仅escape时附加 |

冻结任务头部为48 bit。解码器必须同时校验协议版本、查询数量、码本epoch和16-bit标签。

### 9.2 完整码本安装

完整安装帧编码：

- N、ε、查询集合与允许起点；
- 每个码字的解码动作；
- 完整256-bit SHA-256摘要。

接收端重建码本后重新计算摘要，不一致则拒绝安装。默认部署方式是设备软件预置码本；无线完整安装只用于初始化或上下文恢复。短会话把在线安装作为默认方式会造成负通信收益，已明确排除。

### 9.3 Fail-closed原则

当接收端未安装码本、epoch不一致、标签不一致、查询模式不一致、索引越界或帧有尾随数据时，解码器抛出错误并拒绝动作。所有已运行压力单元中的错误码本动作执行次数为0。

这里的安全只表示“不会执行已识别的错误码本动作”，不表示系统始终可用。拒绝执行可能降低availability和clean rate。

## 10. 有状态事件触发与上下文信念恢复

### 10.1 硬触发

接收端已有动作状态时，发送端计算所有可能接收端状态下的最坏复用regret和最大年龄。出现任一条件即必须更新：

- 任一可能上下文未安装或码本版本错误；
- 最坏复用regret > 0.2 dB；
- 最大状态年龄 > 120分钟。

预测器不能取消硬触发。

### 10.2 接收端上下文信念集合

由于发送端无法确定安装包、更新包或ACK是否成功，它维护一组可能的接收端状态，而不是假定“发送成功即双方同步”。每个假设记录：

- 是否已安装码本；
- 码本epoch；
- 最近更新epoch；
- 当前多查询动作；
- 成功时间戳。

一次安装或更新未收到ACK时，信念集合同时保留“未送达”和“已送达但ACK丢失”分支。若策略要求，还加入“接收端上下文已经丢失”的分支。

### 10.3 累计ACK过滤

ACK为24 bit，包含magic、版本、节点ID和最新成功8-bit纪元。发送端只接受不陈旧的ACK，并用累计纪元过滤不兼容假设。延迟重复ACK不会把发送端状态回退到旧纪元。

如果任一剩余假设未安装或码本epoch不一致，系统执行完整安装恢复；否则按所有假设的最坏regret和最大年龄决定是否更新。

## 11. 固定静默心跳

普通ACK机制无法在长时间静默时主动发现接收端已经重启。冻结系统在连续20个场景没有成功反馈且信念集合尚未要求重装时，发送32-bit探测请求；接收端返回32-bit响应，携带节点、码本epoch和更新epoch。

若探测或响应失败，发送端把“上下文可能丢失”加入信念集合，继而触发保守重装。已有正常ACK可作为隐式存活确认并重置静默计数。

固定H = 20心跳在开发混合故障中使clean rate提高8.084—24.481个百分点，但增加约9.043—14.958 bit/景。它是可靠性组件，不是免费收益。更频繁的H = 10代价过高；自适应心跳只在2/4种N上通过，已排除。

## 12. 轻量频谱风险预测与重复保护

### 12.1 预测目标

预测目标不是下一时刻的精确频谱动作，而是：

> 当前码字动作在下一场景是否会使最大regret超过0.2 dB。

标签只使用t + 1场景生成；特征只使用时刻t及更早信息，避免未来泄漏。

### 12.2 因果特征

特征包括：

- 当前功率均值、标准差、范围；
- 相邻信道功率差的均值和最大值；
- 与上一场景的功率变化均值、最大值和标准差；
- 历史是否可用、时间间隔；
- 上一动作是否已经违规、动作变化比例；
- 当前是否使用escape；
- 各查询最优/次优间隔；
- 当前码字动作在各查询上的regret。

模型为标准化后的平衡类权重逻辑回归。阶段6.4开发AUC为0.806—0.838，平均精度相对最佳简单基线提升0.273—0.320，但面向高召回的操作阈值产生79%—94%的误报率，因此没有直接接入动作控制。

### 12.3 冻结用途

冻结系统只允许预测分数对“自然硬更新的重复保护机会”排序：

1. 先由硬regret/年龄规则决定是否真的需要更新；
2. 预测器不能制造未来动作，也不能让系统静默；
3. 若该更新属于高风险候选且总预约数未超过评估场景的10%，发送同一紧凑更新的重复副本；
4. 任一副本送达即视为更新成功；
5. 误报同样消耗预约容量。

167个评估场景最多预约17次。学习保护在N = 8、16、32上获得95%区间支持，在N = 64上区间跨0。clean增益只有0.100—0.319个百分点，因此只能称为辅助机制。

### 12.4 已排除的预测路线

以下路线因负结果不进入冻结候选：

- 直接下一码字多分类；
- 带拒绝的两阶段目标码字分类；
- 马尔可夫硬频谱动作；
- 马尔可夫更新预约控制器；
- 马尔可夫token bucket；
- 预测结果直接选择未来频谱块；
- 自适应心跳。

一阶马尔可夫在码字分类上达到70.629%—78.322%，但较高分类准确率没有稳定转化为更高的单位预约容量收益。它保留为可解释预测强基线，而不是控制器。

## 13. 当前冻结系统的逐场景完整流程

### 13.1 离线阶段

1. 读取开发缓存，按时间簇拆分训练与评估。
2. 对每个N构造D = 0.25N、0.50N、0.75N三个查询。
3. 对训练场景计算多查询成本、精确最优动作和ε可接受集合。
4. 用贪心覆盖拟合任务等价码本。
5. 生成码本SHA-256、epoch和16-bit包标签。
6. 用因果时序特征训练一步风险逻辑回归；阈值来自训练折外分数上0.1分位点。
7. 将码本、模型、阈值和协议参数冻结到设备软件或实验快照。

### 13.2 会话初始化

1. 优先加载预配置码本。
2. 若接收端没有正确上下文，发送完整安装帧。
3. 接收端重建码本并核验完整SHA-256。
4. 发送端根据信息送达与ACK情况初始化上下文信念集合。

### 13.3 每个场景

1. 将当前功率扫频转成N维信道功率。
2. 计算三个查询的候选块代价和任务状态。
3. 对信念集合中的每个可能接收端动作计算最大regret和状态年龄。
4. 若存在上下文不一致，先恢复安装。
5. 若所有可能状态均满足regret和年龄约束，则静默复用。
6. 否则从码本选择安全码字；无安全码字时使用escape加精确动作。
7. 预测器只对该硬更新的重复保护优先级评分。
8. 若在预算内且属于高风险候选，发送重复副本。
9. 接收端完成身份检查后执行码字动作；任何身份异常均拒绝执行。
10. 发送端用ACK更新信念集合；静默满20景则启动探测。
11. 记录前向bit、ACK bit、预约容量、availability、clean、regret和错误动作次数。

### 15.3 阶段6冻结消融

| 单元 | 作用 |
|---|---|

## 17. 已完成工作的创新性判断

### 17.1 可以作为主要创新候选的内容

1. **多查询任务等价码本。** 系统不要求重构功率谱或逐一传输精确动作，而是用最大regret约束定义多个频谱状态在任务上的等价关系，再用确定性贪心覆盖构造离散码本。
2. **硬风险约束下的有状态语义闭环。** 事件静默、码字更新、码本安装、累计ACK和上下文信念集合共同工作；压缩收益不能脱离接收端状态一致性讨论。
3. **预测与安全控制解耦。** 轻量模型只排序有限冗余保护机会，不能直接执行动作、不能取消硬触发、不能绕过身份检查。这一约束避免预测错误转化为未受控频谱动作。
4. **完整的证据治理。** 明确区分payload、应用层bit、实际链路bit和反馈成本；保留负结果；采用时间簇拆分、配对共同随机数、bootstrap、一次性Final和哈希证据链。

### 17.2 创新强度应谨慎描述的内容

- 最优块坐标本身是简单任务控制信令，单独看不足以构成强算法创新。
- 贪心集合覆盖、逻辑回归、ACK状态机和心跳均不是新算法原语；价值来自它们围绕任务regret、码本身份和接收端不确定性的联合约束。
- 当前码本只有3个码字，开发回退率为0，可能依赖该活动的频谱结构；外部Final可能需要更多escape。
- 学习增益只有0.100—0.319个百分点，不能把“加入机器学习”作为论文主卖点。
- 目前没有完成系统性前向/后向引文检索，不能作绝对首创声明。

## 18. 可行性与工程成熟度

### 18.1 有利证据

- N = 8到64的运行时间和内存没有数量级爆炸；
- 码本、任务更新、安装、ACK和心跳都有真实二进制codec与异常检查；
- 开发结果可由独立输出逐字节复现；
- 323项回归测试在S6.6d记录中通过；
- 设备可预置码本，在线消息只需短标签和epoch；
- 预测模型轻量，推理约1.1—1.3 μs/景。

### 18.2 尚不足以支持部署的证据

- 没有在目标无人机处理器上测量CPU、内存、功耗和端到端时延；
- 没有实测控制链路、ACK、重启和丢包分布；
- 频谱数据虽包含helikite位置，但阶段6没有报告随移动状态的分层性能；
- 没有多节点同步观测或融合中心冲突处理；
- 没有频率法规、发射约束、干扰温度或真实调度执行接口；
- 没有外部Final。

## 19. 必须保留的负结果与限制

1. 阶段3质量感知多节点融合没有稳定优于等权平均，不能作为当前空间协同结论。
2. 阶段4相对4-bit软功率的性能增益很小，主要优势是任务压缩。
3. N = 8时独热/索引的端到端bit优势受固定头部和FEC边界压缩。
4. 阶段5差分编码未降低实际链路bit。
5. 动态查询的单查询事件更新在cyclic压力下未通过，必须使用多查询刷新。
6. 固定重复累计ACK和独立请求在计入控制成本后为负结果。
7. 阶段6完整系统clean只有84.1%—86.2%，CVaR被10 dB掉线惩罚封顶。
8. 接收端重置是最严重故障，重置率5%可使clean下降约30个百分点。
9. ACK丢失下的可靠性依赖显著增加信令。
10. 学习保护收益小，N = 64统计区间跨0。
11. 当前证据主要来自固定站点或单条helikite活动，跨活动泛化未测试。

## 22. 复核建议与待审问题

建议第三方按以下顺序审查：

1. **定义审查**：0.2 dB regret是否是可解释且足够严格的任务容差？平均块功率是否覆盖实际频谱选择的干扰与法规因素？
2. **语义定位审查**：任务等价动作类是否足以称为离散任务导向语义通信，还是更适合称为任务导向控制信令？
3. **算法审查**：候选动作只取开发集精确最优元组，会不会遗漏外部分布中的重要动作？是否需要受约束的码本大小、覆盖保证或在线未知状态检测？
4. **协议审查**：16-bit短标签的碰撞风险、8-bit epoch回绕、幂等安装和重放保护是否足够？
5. **可靠性审查**：信念集合是否在更长会话或更高故障率下状态爆炸？H = 20的发现延迟是否可接受？
6. **统计审查**：clean定义、10 dB掉线惩罚、CVaR封顶和分组bootstrap是否会掩盖条件regret？
7. **基线审查**：是否还需加入率失真、AoI/VoI事件触发、语义ARQ、POMDP或压缩状态估计基线？
8. **创新性审查**：联合方案与任务导向ARQ、goal-oriented资源分配、离散语义码本和状态估计通信文献的差异是否足够形成硕士论文主创新？
9. **外部效度审查**：2024—2025三批数据能否提供城市/农村、移动高度、频段和活动差异；最终分层应该如何预注册？
10. **部署审查**：目标无人机平台的计算、存储、能耗、链路和重启分布应如何测量？

审查者应优先回答以下决策问题：

- 阶段6是否已经达到“可进行一次外部Final”的算法冻结程度？
- 外部Final主比较应固定为哪个可靠性工作点，怎样避免拿低clean换低bit？
- 哪些缺陷必须在Final前修复，哪些只能作为已知限制进入论文？
- 机器学习辅助模块是否值得保留在主算法，还是应降级为扩展消融？
- 若外部Final失败，应把失败解释为码本泛化、上下文恢复、数据适配还是统计功效问题？

## 23. 交接结论

截至2026-07-27，系统已经形成一套可运行、可审计的离散任务导向频谱资源控制算法。它从真实功率扫频计算多查询连续块代价，用0.2 dB regret定义任务等价状态，以2-bit联合码字压缩多查询动作，并通过escape、版本化身份、信念状态、累计ACK和固定心跳维持共享上下文。轻量逻辑回归只负责把有限冗余优先分配给高风险更新。

当前最强的已确认结果仍是阶段4同活动跨日期Final。阶段6的主要进步是算法与协议完整性，而不是已经获得外部泛化结论。阶段6开发候选通过14项门槛、323项测试和确定性复现，具备注册外部Final协议的条件；但同clean rate端到端bit优势、跨活动泛化、真实移动与真实ACK可靠性仍未成立。第三方审核应围绕“任务语义定位是否充分、可靠性工作点是否公平、外部Final协议如何避免事后选择”给出后续建议。
