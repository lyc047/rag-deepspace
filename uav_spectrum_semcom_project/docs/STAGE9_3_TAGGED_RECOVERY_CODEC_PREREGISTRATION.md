## 1. 目标

阶段9.3将阶段9.2的 S9-RST16-BL128-v1 从符号模型落实为真实二进制 codec 和独立接收端进程。任务码本、普通42 bit更新、24 bit ACK 和30景看门狗均保持不变。

## 2. 二进制变化

会话身份由8 bit发送端控制器代次、16 bit接收端 boot ID 和8 bit目录版本组成。对固定宽度身份输入计算 SHA-256，并取前16 bit作为恢复会话标签。

- 预安装激活：64 bit增加到80 bit；
- N = 32、K = 3、三查询完整安装：403 bit增加到419 bit；
- 普通紧凑更新：保持42 bit；
- 普通累计ACK：保持24 bit。

16 bit截断哈希只用于发现意外旧会话，不提供抗伪造认证。

## 3. 接收端要求

- 恢复包到达时重新核对当前 boot ID 和目录版本；
- 目录持久文件带完整 SHA-256校验；
- 文件损坏或无法解析时 fail-closed；
- 更新序号采用8 bit半窗口规则；
- 旧包最大可投递年龄为127次更新；
- 建立新恢复会话时清空延迟队列；
- 当前更新的完全相同副本允许幂等ACK。

## 4. 验证

先执行固定进程场景，再执行随机对抗轨迹。开发200条、确认500条，每条200步；确认种子和程序必须在开发后冻结。

验收要求：所有安全违例、旧恢复误接收、错误目录恢复误接收和损坏目录可执行次数均为0；标签帧位宽必须精确为80和419 bit；普通更新与ACK位宽不得改变。
