# 阶段 3：关联多 UAV 观测与质量感知融合

## 1. 阶段定位

阶段 0、1、2 已分别完成论文边界、可复现实验协议和公平数字链路。阶段 3
直接验证 H3：在同一频谱场景的关联多节点观测上，质量感知融合能否在相同
报告集合和总上报预算下优于 OR、多数投票、等权平均和固定 SNR 加权。

本阶段不再使用四个无关 RadDet 帧叠加来声称多 UAV 协同。第一步以同一底层
谱图构造不同 SNR、增益和频偏的节点视图，建立可审计的半合成诊断协议；最终
证据必须替换为同步多接收机或同源记录回放数据。

## 2. 分步计划与验收

### S3.1 协议与经典融合基线（当前执行）

1. 冻结同场景节点生成参数、节点数和随机种子；
2. 所有融合方法共享完全相同的本地检测结果和成功送达报告；
3. 实现 OR、多数投票、平均、SNR 加权和解析质量加权；
4. 报告 clean rate、regret、oracle-equivalent rate、总发送 bit 和置信区间；
5. 明确半合成数据不能作为真实飞行结论。

验收：经典规则具有单元测试；同一配置可复现；质量加权不得使用真实标签作为
输入；测试集不用于设计权重。

### S3.2 关联数据建立

1. 优先采用同一 I/Q 记录经多条可控信道回放；
2. 条件允许时使用一个信号源和 2--4 个 SDR 同步接收；
3. 保存 scene ID、node ID、时间戳、位置、感知 SNR、频偏和同步误差；
4. 按 scene/recording 划分 train、val、test，禁止节点视图跨集合泄漏。

验收：至少 3 种节点异质性、2 种场景密度和 4 个节点规模；同一 scene 的节点
具有共同真值并保留可追溯记录。

### S3.3 学习式质量感知融合

1. 输入节点占用、置信度、SNR、上报成功概率、位置和信息年龄；
2. 先实现 DeepSets/attention pooling，避免过早引入复杂 GNN；
3. 使用资源 regret、漏占用惩罚和校准损失联合训练；
4. 与解析质量加权比较，证明收益来自学习而非额外信息。

验收：验证集选择模型；在相同报告和 bit 预算下，测试集 regret 显著低于最强
经典基线，或明确给出无显著收益的负结果。

### S3.4 鲁棒性与失效边界

执行节点数 1/2/4、感知 SNR 异质性、上报链路异质性、节点失效、过期报告、
异常节点和域偏移 sweep。所有主要结果至少 5 个种子并报告 95% 置信区间。

### S3.5 阶段出口

阶段 3 完成需同时满足：关联数据无 scene 泄漏；经典与学习融合公平；质量信息
不含测试真值；有完整消融和失效边界；真实或记录回放证据与半合成结果分开表述。

## 4. 首次 smoke 结论（2026-07-12）

50 个稀疏 RadDet 场景、4 个关联节点视图和 5 次重复已运行。多数投票为
0.948 clean rate、0.002260 regret；其余 OR、平均、SNR 加权和解析质量加权
均达到 1.0 clean rate、约 0.000103 regret，出现明显任务饱和。

该结果只证明关联场景、数字上报和融合评测管线正确，不能证明质量感知方法优于
经典融合。正式实验在进入学习模型前必须先完成以下难度审计：

1. 使用验证集选择而非测试集选择资源任务难度；
2. 将候选信道从 4 扩展到 8/16，并扫描连续资源需求；
3. 增加高占用或多目标同场景数据；当前本地仅有稀疏 HW001 数据；
4. 增加单个高 SNR 但差上报、低 SNR 但新鲜等交叉异质性；
5. 加入节点失效、过期和异常高置信报告；
6. 只有最强经典基线不再饱和，才训练和评价学习式质量融合。

若在合理难度下平均/OR 仍与 oracle 等价，应报告“融合策略非瓶颈”的负结果，
而不是通过任意加噪人为制造所提方法优势。

## 5. 验证集难度选择（2026-07-12）

仅在验证集比较了 2/4 个源帧合成、4/8 个候选信道、连续需求为 2 的四个候选。
2 源场景中最强经典融合的 clean rate 为 0.89--0.92，任务偏容易；4 源、8 信道
时 regret 较高且质量加权未改善，任务偏不稳定。冻结 4 源、4 候选信道、连续
2 信道需求：mean/OR clean rate 约 0.773、regret 约 0.0129，多数投票更差，
既未饱和也未接近随机下限。

该选择仅依据经典融合的难度区间，不依据质量加权是否获益；正式测试固定为 200
个合成场景、4 个节点和 5 次重复。验证集明细位于
`results/stage3/difficulty_audit/`。

## 6. 经典融合与学习融合初步结果（2026-07-12）

冻结测试中，4 源合成、4 节点、4 候选信道、连续 2 信道需求下，等权平均为
clean rate 0.792、regret 0.009309；解析质量加权为 0.791、0.009306，未形成
有意义的优势。所有方法的实际发送量相同，约 3347 bit/decision。

随后使用源帧完全不重叠的 train/val/test 构造 DeepSets pilot。测试集上，mean
和 SNR 加权均为 clean rate 0.805、regret 0.008464，而 DeepSets 为 0.735、
0.013131。该负结果被保留，不据此调整已使用的测试子集，也不能宣称学习式融合
优于经典方法。

当前解释是：受控节点视图仍高度相关，检测器未输出可区分的置信度，且报告可靠性
在“成功送达后再融合”的协议中信息增益有限。下一轮仅在新的验证/保留测试场景上
研究以下改进：检测概率校准作为节点置信度、时序陈旧观测、节点异常/失效、以及
同源记录回放或同步多接收机数据。

## 7. 独立留出集鲁棒性结果（2026-07-16）

为避免继续使用先前已消费的前 800 个 test 源帧，新增
`configs/stage3_holdout_registry.json`，冻结 test 源偏移 1200 开始的 200 个
滑动时序场景。相邻场景共享 3/4 个源帧，使陈旧节点实际携带历史频谱观测，而非
只附加年龄标量。检测掩膜的无标签原始置信度只在 val 偏移 1200 的 80 个场景上
映射为“单节点资源选择 oracle 等价概率”。校准使验证集 Brier/MSE 从 0.307967
降至 0.227169，在新留出集从 0.412519 降至 0.266312，但仍存在明显域偏移。

冻结实验包含 200 个场景、5 次重复和 7 类条件。基准四节点下，等权平均为
clean rate 0.789、regret 0.008752，质量感知为 0.790、0.008772；配对 regret
差为 +0.000021，95% CI 为 [-0.000277, 0.000319]，无显著优势。两节点异质
条件下质量感知的 regret 差为 -0.000088，区间仍跨 0。所有场景均未满足预先
冻结的“H3 成功区间低于 0”规则。

高置信错误节点是明确失效边界：质量感知相对等权平均的 regret 增加
0.000411，95% CI [0.000194, 0.000627]，说明乘积权重会放大错误元数据。
最佳单节点仅需约 844 bit/decision，clean rate 0.793、regret 0.008666；四节点
质量融合约需 3376 bit/decision，却未改善任务性能。因此当前证据不支持“融合
节点越多越好”，反而支持下一步研究价值/bit 节点选择、异常一致性门控和保守
权重裁剪。

阶段结论保持为负结果：解析质量加权和 DeepSets 均未证明优于最强经典基线，H3
尚不成立。下一步不得根据本留出集继续调权；应新建 validation/holdout 版本，并
优先获得同源 I/Q 回放或同步多接收机数据。完整结果位于
`results/stage3/robustness_holdout/`。

## 8. 价值/bit 节点选择与一致性鲁棒融合（2026-07-16）

在全新的 val 源偏移 2000 上比较了选择 1/2/3/4 个节点、三种一致性尺度和三种
权重裁剪范围。调度分数只使用验证集冻结的节点任务正确率、链路可靠性、年龄和
预期发送 bit，不读取当前占用或测试真值。验证规则最终选择 2 个节点；随后仅在
test 源偏移 3000 的 200 个新时序场景上执行 5 次重复。偏移 2000 的 20 个诊断
场景已登记为消费数据，未被复用为正式结论。

正常四节点条件下，所提选择融合从 3297.9 降至 1486.8 bit/decision，减少
54.9%；clean rate 为 0.721（全节点平均 0.722），regret 为 0.009642（全节点
平均 0.009366）。配对 regret 差为 +0.000276，95% CI
[-0.000342, 0.000894]，未形成显著差异，也未满足严格的 0.0005 非劣界上限。

失效条件仍然明确：最佳节点失效时 regret 显著增加 0.000941；高 SNR 节点陈旧
时显著增加 0.001460。验证选择仅保留两个节点，因此三节点以上的中位数一致性
门控不被启用；在相同两节点和相同 bit 下，鲁棒质量权重相对等权平均的所有配对
置信区间均跨 0，说明当前收益主要来自少发节点，而不是鲁棒融合算法。

因此本轮只支持有限结论：价值/bit 调度在正常条件下具有约 55% 的通信节省潜力，
但尚未获得统计非劣保证，且缺少节点失效后的候补调度。不得把该结果写成 H3 空间
协同增益。下一版必须在新的验证/留出范围研究 ACK 触发的候补节点、最少三节点
一致性仲裁和异常情况下的动态预算回退。

## 9. ACK 候补与风险回退（2026-07-16）

第三轮仅在 val 源偏移 3000 选择策略，在冻结前未读取 test 偏移 4000。协议初始
调度两个价值/bit最高节点；若成功送达不足两份，则依据 ACK/解码结果依次补发；
若发生送达失败、报告陈旧或节点分歧，则扩展仲裁节点。验证集中，两节点按需分歧
触发不能满足预设非劣约束，最终冻结为目标 3 份报告、鲁棒质量融合；分歧阈值为 0，
等价于正常场景默认三节点仲裁，在失败时继续尝试第四节点。

正式实验使用 test 偏移 4000 的 200 个新时序场景和 5 次重复。正常四节点下，所提
方法为 clean rate 0.767、regret 0.012965、2397.8 bit/decision；全节点平均为
0.763、0.013133、3427.9 bit/decision。发送量减少 1030 bit（30.0%），配对
regret 差 -0.000168，95% CI [-0.000401, 0.000065]，性能差异不显著。

最佳节点失效和组合异常时，ACK 回退尝试全部 4 个节点，发送量分别与全节点基线
相同，regret 差为 +0.000033 和 -0.000030，置信区间均跨 0。高置信错误及高
SNR 陈旧条件仍节省约 1030 bit，且相对全节点平均无显著 regret 差异。因此相比
固定两节点方案，自适应回退消除了“关键节点失效或陈旧时显著恶化”的主要问题。

机制消融仍显示：在完全相同调度与 bit 下，鲁棒质量融合相对自适应等权平均的所有
regret 差异置信区间均跨 0。当前可以支持的贡献是“验证先验驱动的三节点节流与
ACK 失效回退”，不能声称一致性加权显著优于平均融合，也不能证明真实空间协同
H3。完整结果位于 `results/stage3/adaptive_fallback_holdout_v3/`。

## 10. 同源真实 I/Q 记录回放与时延能耗（2026-07-16）

使用本地一条真实 5G NR SigMF I/Q 录制的 14 个连续切片，建立四节点同源回放。
每个节点从完全相同的原始 I/Q 出发，分别经过可审计的增益、载波频偏、多径和复
高斯噪声，再执行 STFT、冻结能量检测、频谱语义上报、数字链路和资源选择。该数据
只有一个 source recording，且原有 train/val/test 切片来自同一录制，因此仅用于
记录回放接口和失效诊断，不用于独立泛化或真实空间协同结论。

冻结检测器在 -3/3/9/15 dB 四节点上的 F1 分别为 0、0、0、0.338，显示原有
检测规则在 I/Q 信道扰动后存在显著域偏移。四种调度策略的 clean rate 均为
0.7143、regret 均约 0.002459，说明这条短记录上的四信道资源任务对策略不敏感，
不能用于区分融合优劣。

尽管任务指标饱和，通信代价接口已补齐。全节点平均需要 3769 bit/decision、
2.66 ms 链路时延和 1.884 mJ 的 1 W 参考 RF 能量；ACK 自适应三节点需要
2744 bit、另加 97.4 bit 调度反馈、5.04 ms 和 1.372 mJ。即上行 bit 与参考
RF 能量减少约 27%，但串行反馈使时延增加约 90%。固定两节点仅需 1973 bit，
但当前任务饱和使其表面性能相同，不能据此证明两节点已足够。

本轮完成了同源 raw-I/Q 到多节点语义决策的工程闭环，并量化了“节省上行能量但
增加 ACK 等待时延”的权衡。下一项外部缺口仍是多条独立录制或同步多接收机数据；
同时需要在多占用状态下重建不饱和资源任务并重新校准检测器。完整结果位于
`results/stage3/iq_record_replay/`。

## 11. 本地多设备数据资格审计（2026-07-16）

进一步检查了本地 FIESTA 的 8 台设备和 525/575/625/675/725/775 MHz 六个频段。
按设备和中心频率流式读取时间戳后，525、575、625、725、775 MHz 均不存在两个
设备共享的精确秒级时间戳；675 MHz 仅有 1 个双设备同秒样本，设备为 saber 与
saki，其中 saber 的经纬度为 0/0，无法验证二者处于同一场景。没有任何三节点或
四节点同步样本。

因此 FIESTA 在当前项目中只能用于多设备独立频谱分布和语义载荷统计，不能用于证明
同场景空间协同 H3。阶段 3 剩余的正式证据无法通过现有本地数据补齐，需要新增多条
可对齐录制、同源信号回放采集，或 2--4 台 SDR 同步接收实验。

## 12. LoRaIQ 真实四接收机 pilot（2026-07-16）

已从公开 LoRaIQ 数据集中接入 2 次无人机发射，每次均有 4 个真实 RRH 的对齐
`cf32_le` I/Q。实验不再对单条记录人为生成节点信道，而是直接保留真实空间传播、
前端和接收质量差异。每个节点生成 4 维 8 bit 占用概率语义，并通过阶段 2 的统一
数字链路完成节点选择、量化恢复、融合和资源选择。

20 次链路随机重复中，全节点等权平均、SNR 加权和鲁棒质量加权的 F1 分别为
0.5417、0.8500 和 0.6161；动态最佳单节点为 0.8889。所提自适应价值/bit 方法为
0.7500，上行 bit 从全节点的 2803.5 降至 1890.0，节省约 32.6%，但串行 ACK/候补
使时延由 1.98 ms 增至 4.05 ms。NLoS 事件中只有一个 RRH 正确检出，一致性门控
会将其当作离群点压制，说明当前鲁棒融合仍不是最强方法。

两个事件均占用中心半带，资源 clean rate 和 regret 对所有策略饱和；阈值也在同一
pilot 上检查过。因此该实验只作为真实多接收机闭环与失效机制证据，不建立 H3。
完整结果位于 `results/stage3/loraiq_pilot/`，解释见
`docs/STAGE3_LORAIQ_PILOT_CONCLUSION.md`。
