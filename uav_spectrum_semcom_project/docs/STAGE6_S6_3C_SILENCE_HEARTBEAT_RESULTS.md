## 1. 研究问题

S6.3b能够根据任务包和ACK的不确定性恢复上下文，但接收端若在长期静默期间重启，发送端看不到任何失败证据。此时系统虽不会错误解码，却可能长期没有可执行动作。S6.3c因此研究两个联合机制：

1. 已有安装ACK或任务ACK作为隐式存活确认，不增加额外比特；
2. 连续若干场景没有收到任何新鲜确认时，发送固定长度探测请求。

目标不是把“没有响应”武断地解释为接收端重启，而是把“上下文可能已经丢失”加入发送端信念集合，再由S6.3b的最坏情况风险规则决定恢复。

## 2. 真实协议与状态机

### 2.1 32-bit探测请求

| 字段 | 长度 |
|---|---:|
| 请求标识 | 8 bit |
| 协议版本 | 2 bit |
| 节点编号 | 6 bit |
| 码本epoch | 8 bit |
| 发送端预期的任务更新epoch | 8 bit |

### 2.2 32-bit探测响应

| 字段 | 长度 |
|---|---:|
| 响应标识 | 8 bit |
| 协议版本 | 2 bit |
| 节点编号 | 6 bit |
| 接收端码本epoch | 8 bit |
| 接收端当前任务更新epoch | 8 bit |

只有在码本上下文、任务动作和更新epoch均存在时，接收端才返回响应。请求与响应均调用真实二进制编解码器，而不是在仿真中直接增加一个理想化常数。

### 2.3 触发与恢复规则

设静默阈值为H个场景。每收到一次新鲜安装ACK、任务ACK或有效探测响应，静默计数清零。当静默计数达到H且发送端当前仍相信码本已经安装时，发送探测请求。

- 响应成功：用响应中的码本epoch和更新epoch筛除不相容的接收端状态；
- 没有响应：保留原有状态，同时加入“上下文未安装”假设；
- 只要可能状态中存在上下文未安装，立即进入幂等码本重装；
- 任何不匹配码本或epoch的数据仍被拒绝，保持fail-closed。

因此，探测失败只增加不确定性，不等价于已经证明接收端重启。

## 3. 实验设计

- 信道规模：N = 8、16、32、64；
- 每个N设置25%、50%、75%三种连续信道需求；
- 任务regret上限：0.2 dB；
- 测试场景：167个，按完整轨迹进行30次配对蒙特卡洛；
- 故障条件：安装包丢失10%、任务包丢失10%、ACK丢失20%、延迟重复ACK 10%、每场景接收端上下文重置2%；
- 比较策略：无心跳、静默10场景、20场景、40场景；
- 应用层开销：请求32 bit、响应32 bit、ACK 24 bit、码本重装和任务更新均按真实编码长度计数；
- 不可用场景的有效regret固定记为10 dB，但同时单独报告可用率和条件regret。

四种策略在同一条轨迹上使用相同的故障随机数。无心跳组逐指标精确复现S6.3b冻结结果，排除了随机轨迹改变造成的伪增益。

## 5. 配对轨迹统计

以完整167场景轨迹为重采样单位，进行10,000次配对cluster bootstrap。以下为相对无心跳的clean rate提升及95%区间：

| N | H=10 | H=20 | H=40 |
|---:|---:|---:|---:|
| 8 | 28.62 [22.89, 34.63] | 22.77 [17.80, 27.74] | 13.43 [10.16, 16.61] |
| 16 | 13.11 [9.78, 16.59] | 7.47 [4.99, 10.08] | 1.78 [1.24, 2.30] |
| 32 | 12.85 [9.46, 16.37] | 7.76 [5.57, 10.18] | 1.60 [1.16, 2.04] |
| 64 | 10.92 [7.58, 14.31] | 6.97 [4.73, 9.30] | 1.58 [1.10, 2.04] |

全部区间均高于0，说明在本次固定合成故障模型内，改善不是少数轨迹造成的偶然均值。同时，总比特差异的全部95%区间也高于0，因此不能把可用性提升描述为“无代价”。

这些区间只度量固定合成故障模型下的蒙特卡洛轨迹不确定性，不是现实无人机链路总体的置信区间。

## 6. 结论与下一步

S6.3c解决了S6.3b的结构性缺口：系统现在能够在没有任务ACK证据时主动发现“可能的上下文丢失”，并在错误执行次数保持为0的前提下显著提高可用率。

结果同时否定了“固定高频心跳可以直接作为最终方案”。较短阈值带来的主要成本不是32-bit探测本身，而是探测请求或响应丢失后触发的保守重装。下一步不应继续盲目缩短H，而应研究：

1. 根据估计的重启风险、当前业务活跃度和控制预算自适应选择探测时机；
2. 在普通上行业务中捎带上下文摘要，减少独立探测；
3. 将预测器只用于调整探测或更新时机，安全决策仍由最坏情况regret约束兜底；
4. 在测得的链路丢包和设备重启统计上重新标定，之后再冻结统一Final协议。

当前保留H=10、20、40作为灵敏度基线，不依据本轮开发结果冻结唯一阈值。
