# 阶段 3 本地多设备数据资格审计

## 审计对象

本地 FIESTA 数据包含8台设备：berserker、caster、gglPixel2、lancer、pikachu、
rider、saber、saki。每台设备包含525、575、625、675、725、775 MHz六个中心频段，
每条记录由经纬度、Unix秒级时间戳和256个频谱功率值组成。

## 同步性检查

按相同中心频率比较所有设备的精确时间戳交集：

| 中心频率 | 设备数 | 多设备共享时间戳数 | 同时设备上限 |
|---:|---:|---:|---:|
| 525 MHz | 8 | 0 | 1 |
| 575 MHz | 8 | 0 | 1 |
| 625 MHz | 8 | 0 | 1 |
| 675 MHz | 8 | 1 | 2 |
| 725 MHz | 8 | 0 | 1 |
| 775 MHz | 8 | 0 | 1 |

675 MHz唯一共享时间戳为1646058012，涉及saber和saki。saki记录的位置为
43.060237、-89.467215，而saber位置为0、0，因此无法确认两台设备处于同一地点或
观察同一辐射场景。

## 结论

现有FIESTA数据不是同步多接收机数据，没有三节点或四节点同时观测，不能作为多无人机
同场景融合证据。允许的用途包括：

- 不同设备频谱分布对比；
- 单节点域偏移研究；
- 频谱事件语义载荷统计；
- 非同步众包频谱地图研究。

禁止将不同设备、不同时间的记录直接拼接后声称空间协同增益。要完成阶段3正式H3
证据，必须新增可追溯的同源记录回放或同步多SDR采集。
