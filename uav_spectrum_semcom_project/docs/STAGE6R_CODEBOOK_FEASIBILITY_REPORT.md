# S6R码本泛化与AI辅助上下文适配研究报告

版本：1.0  
日期：2026-07-28  
证据状态：开发实验完成，不是新Final

## 1. 研究目的

阶段6外部修复性验证的escape率达到99%，说明基于2023单活动构造的固定三码字码本不能直接迁移到2024—2025活动。本研究依次回答三个问题：

1. 固定动作码本在数学上是否存在；
2. 失败来自候选动作不足、码本规模不足，还是活动间动作映射改变；
3. 能否通过轻量上下文学习选择或安装活动适配码本，同时保留精确regret安全层。

数据由2023年364景和已经消费的2024—2025年200景组成。全部仅作为开发数据；活动级留一用于泛化诊断，任何结果均不得称为新的外部Final。

## 2. 方法

任务状态包含三种需求比例：D/N = 0.25、0.50、0.75。候选动作是三个连续块起点组成的动作元组。某码字只有在下式成立时才允许发送：

`max[q] R(x,q,a_q) ≤ 0.2 dB`

若所有码字都不满足条件，系统发送escape和精确动作。因此所有实验的错误码本动作数理论上和实测均为0。

第一项实验比较：

- 仅使用训练集精确最优动作；
- 使用训练集ε可接受动作并集；
- 穷举全部合法动作；
- 在留出活动未来数据上拟合的oracle上界。

第二项实验按时间顺序使用前B景校准，后续场景只用于评价。B取1、2、4、8、16、32，K取3、4、8，并显式计入校准期精确动作与新码本安装载荷。

第三项实验构造轻量上下文模型：

1. 每景功率谱减去其中位数并按标准差归一化；
2. 对校准景取平均，形成活动频谱形状特征；
3. 以训练活动特征中心形成预装码本库；
4. 使用最近中心选择码本；
5. OOD阈值只由训练活动中心间距离确定；
6. 超过阈值时，用校准景安装新码本；
7. 运行期仍逐景执行精确regret校验和escape。

该模型属于AI辅助的上下文识别与安全适配，不是端到端神经码本。

## 3. 固定码本可行性结果

### 3.1 K = 3时的活动级留一结果

| N | 解析码本宏平均覆盖 | 解析码本最差活动覆盖 | 活动内oracle宏平均覆盖 | 活动内oracle最差覆盖 |
|---:|---:|---:|---:|---:|
| 8 | 73.60% | 4.95% | 99.24% | 96.97% |
| 16 | 63.85% | 4.95% | 98.05% | 95.52% |
| 32 | 59.18% | 4.40% | 98.12% | 95.52% |
| 64 | 66.22% | 10.16% | 98.12% | 95.52% |

### 3.2 K扩大后的结论

- K = 4时，活动内oracle已达到约99%—100%覆盖；
- K = 8时，跨活动解析码本宏平均覆盖约78%—79%，最差活动仍只有约19%—22%；
- K继续增加至64没有改善，因为训练活动中没有收益的低端动作不会被选入；
- 扩展至ε可接受动作并集或穷举候选没有稳定优于“训练集最优动作候选”。

因此，原假设“H1候选集合过窄”不成立。真正问题是活动条件改变后，固定码字到绝对频谱坐标的映射发生了变化。

## 4. 动作映射诊断

N = 64时，不同活动的oracle代表动作具有明显分区：

- 2023活动主要位于低频率索引，例如`[0,0,0]`、`[10,10,0]`；
- 2024—2025活动主要位于高频率索引，例如`[42,32,16]`、`[48,32,16]`。

类似差异在N = 8、16、32均存在。由此可知：

> 每个活动内部只需很小的固定码本，但不存在由当前三组训练活动自然推出所有新活动绝对坐标的单一全局码本。

这不是语义思想失效，而是“固定绝对动作语义”缺少活动上下文。后续码字应被解释为“某上下文码本中的任务动作”，并由码本身份、版本和安全escape共同保证可执行性。

## 5. 少样本适配结果

单独用少量校准景新建码本并不稳定。K = 4时：

- B = 1或2时，部分活动未来覆盖低至约3%—6%；
- B = 4时，宏平均覆盖约85%，最差约62%—74%；
- B = 16时，多数N的宏平均覆盖约87%—95%；
- B = 32时，宏平均覆盖约96%—98%，最差约91%—94%。

硬规则“校准覆盖率低于90%就新建码本”在B = 2—8时出现非单调失败。原因是个别早期异常景会把本来可复用旧码本的活动误判为新域，而由少量异常景构造的新码本反而不能覆盖未来。

因此，“一个场景即可适配”不能作为稳健结论。

`K = 4，至少连续校准4景，并增加时间一致性门控`

该工作点只是下一原型的起点，不是冻结系统参数。

## 7. 学术判断

### 7.1 已得到支持

- 小型固定动作码本在活动内部具有很强可行性；
- 跨活动失败主要来自上下文相关的绝对动作映射，而非K过小或候选穷举不足；
- “码本库 + 上下文选择 + OOD新建 + 精确安全投影”是合理架构；
- 轻量上下文特征能够恢复大部分活动级泛化；
- 安全层确保所有开发实验的错误码本动作数为0。

### 7.2 尚未得到支持

- 尚未证明完整阶段6协议下仍有同clean rate总bit优势；
- 尚未证明B = 4对更多活动、地点和频段稳定；
- 尚未证明神经网络或复杂VQ优于轻量上下文模型；
- 尚未完成全新未访问数据上的确认性Final；
- 当前仅有4个空中活动，不能把活动分类准确率解释为通用泛化能力。

## 8. 下一步研究计划

### S6R.3a：时间稳定上下文门控

1. 将单一前缀均值改为两个连续子窗口；
2. 只有两个窗口的码本选择一致或OOD判断一致时才安装/复用；
3. 不一致时继续使用精确动作并延长校准；
4. 比较固定B = 4、动态停止和B = 8；
5. 主要指标为最差活动覆盖、校准长度、安装bit和错误安装次数。

### S6R.3b：regret感知候选排序器

1. 对每个“上下文—候选动作”构造特征；
2. 标签使用未来窗口内`R ≤ ε`的覆盖概率与条件CVaR；
3. 首先比较逻辑回归、梯度提升树和小型MLP；
4. 输出候选动作排序，不直接绕过解析验证；
5. 从排序前列中用集合覆盖选出K = 4动作；
6. 活动级外层留一，训练活动内部完成模型和阈值选择；
7. 与解析贪心、码本库、上下文OOD适配和oracle比较。

排序目标为：

`score(a) = 未来安全覆盖概率 − λ₁ × 条件CVaR − λ₂ × 安装与escape开销`

其中λ₁和λ₂只允许在训练活动内部选择。

### S6R.3c：完整协议回接

候选排序器只有同时满足以下条件才回接阶段6协议：

- 四个N的错误码本动作数均为0；
- 至少三个N的最差活动覆盖不低于90%；
- 相同clean rate下总bit低于精确动作基线；
- 计入ACK、心跳、安装、恢复和重传后仍形成更优Pareto工作点；
- 在新活动上不能确认时安全退化为精确动作。

## 9. 与近期研究的关系

近期任务导向码本研究强调直接优化任务损失、码率和码字利用率，而不是仅最小化信号重建误差；决策聚焦学习则强调使学习目标与最终组合决策质量一致。本项目借鉴这些原则，但不复制其网络或损失结构，具体差异在于：

- 本项目码字解码为多查询连续频谱块动作；
- 任务损失由可验证的regret阈值定义；
- 接收端存在码本版本、ACK信念和上下文失步问题；
- AI只负责上下文识别与候选排序；
- 最终动作始终经过解析安全投影并允许精确escape。

## 10. 当前结论

本轮研究不支持“直接训练一个全局VQ码本”，而支持如下分层路线：

`频谱上下文识别 → 选择预装小码本或触发少样本安装 → 发送紧凑码字 → 精确regret验证 → 不安全时escape`

这条路线既利用人工智能处理跨活动分布变化，又保留现有系统最重要的可解释性和安全边界。时间稳定门控已经在S6R.3a完成并通过开发门槛，详细结果见`docs/STAGE6R_TEMPORAL_CONTEXT_GATE_REPORT.md`。下一阶段进入regret感知候选排序器。
