## 1. 验证目的与证据边界

首次阶段6外部Final在第135景中止。2025数据采用“只保存功率向量、由全局元数据定义频率轴”的SigMF结构，而原适配器只支持“频率数组与功率数组拼接、由annotations标记范围”的2023—2024结构。

本次工作只解决这一数据格式差异，然后在不修改核心算法、码本、ε = 0.2 dB、任务查询、故障模型、可靠性工作点、场景清单和统计规则的条件下，完成原登记200景的运行。

由于适配器是在观察外部元数据不兼容之后新增，且同一场景清单被再次访问，本结果只能称为“外部修复性验证”，不能称为“单次外部Final”或替代未来全新数据上的确认性Final。

## 2. 适配器修复

### 2.1 两种数据布局

2023—2024布局：

`SigMF data = 频率数组 + 功率数组`

2025布局：

`SigMF data = 功率数组`

2025频率轴由以下全局字段确定：

- `aerpaw:freq_start`：起始频率，单位Hz；
- `aerpaw:freq_stop`：终止频率，单位Hz；
- `aerpaw:bin_width`：频率间隔，单位Hz。

### 2.2 修复方法

新增独立模块 `aerpaw_helikite_repair.py`：

1. annotations存在时，完全调用原冻结适配器；
2. annotations为空时，要求三个AERPAW频率字段完整且有限；
3. 根据频率跨度和bin width计算预期采样点数；
4. 要求数据长度与预期点数一致；
5. 要求末端频率误差不超过半个频率bin；
6. 验证SigMF SHA-512；
7. 将Hz频率轴确定性转换为MHz；
8. 不读取任务结果，不改变任何算法参数。

原阶段5/6冻结适配器已恢复到原SHA-256和原字节数。新的修复验证快照包含104个文件，原冻结文件变化数为0，新增修复适配器数为1。

这说明系统在2025活动中仍维持了clean与安全性，但几乎没有形成bit优势。

## 7. 正结果、负结果与结论

### 7.1 正结果

- 跨版本适配器能够无异常处理完整200景；
- 三活动和四种任务规模的执行链闭环成立；
- clean点估计稳定在96.57%—97.00%；
- 所有clean 95%下界均高于90%；
- 错误码本动作执行次数为0；
- 2024两个活动仍表现出约13%—23%的活动级bit节省；
- 分析结果可以确定性复算。

### 7.2 负结果

- 四个N的bit节省95%下界均跨越0；
- 没有任何N满足原验收模式；
- 2025活动没有稳定bit优势；
- 外部escape率达到99%；
- N ≥ 16时外部精确动作元组全部未在2023码本训练动作元组中出现；
- 当前固定三码字结构不具备跨活动直接泛化证据。

### 7.3 客观结论

本次结果证明：

> 当前系统的安全回退、事件触发和上下文可靠性机制具有跨活动可运行性，但固定三语义码字的跨活动泛化失败；总体bit节省只有正点估计，没有获得95%置信水平下的稳定正收益。

因此不能声称“阶段6外部有效性已经成立”，也不能声称“语义码本在真实跨活动数据上显著节省总bit”。可以声称的是：

> 系统形成了高clean、零错误码本动作和约11%—13%总bit节省点估计，但跨活动统计区间与2025活动结果表明优势尚不稳健。

## 8. 统计解释边界

1. 外层独立活动只有3个，跨活动bootstrap区间天然较宽；
2. 60条链路轨迹属于受控故障重复，不是60个独立真实活动；
3. 200景经过时间间隔筛选，但不能视为200个完全独立活动；
4. ACK、丢包与接收端重置仍是注入故障，不是数据集实测链路；
5. 本结果经历外部适配器修复，只能承担探索性和修复性证据；
6. 不应通过只报告点估计、只报告2024活动或只报告clean来掩盖总体未通过；
7. 不应把99% escape条件下的系统收益全部归因于语义码本。
