## 2. 公平比较规则

对目标clean c*，语义方案和精确动作方案均须满足：

`95% clean下置信界 ≥ c*`

在各自满足约束的真实工作点中，选择资源等效bit最小者。节省率为：

`Savings = 100 × (Bexact − Bsemantic) ÷ Bexact`

表中置信区间来自60条配对链路轨迹的5,000次bootstrap。所列结果均同时满足实际bit与资源等效bit结论方向一致；入选工作点的风险预留比例均为0，因此两种bit口径数值相同。

## 3. 主要正结果

### 3.1 90% clean目标

预配置码本条件下，四种N均找到显著正节省工作点：

| N | 会话条件 | 资源bit节省率 | 95%区间 |
|---:|---|---:|---:|
| 8 | L = 20 | 7.1% | 2.1%—11.8% |
| 16 | L = 20 | 7.8% | 3.8%—11.8% |
| 32 | L = 20 | 6.2% | 1.7%—10.5% |
| 64 | L = 100 | 19.7% | 15.9%—23.1% |

这说明当前系统在较严格但可达到的90% clean约束下，不再只是“低bit但可靠性更低”的交换；至少在开发pilot的预配置模式中，任务语义工作点位于更优的公平前沿。

### 3.2 85% clean目标

预配置码本的最强正结果为：

| N | 会话条件 | 资源bit节省率 | 95%区间 |
|---:|---|---:|---:|
| 8 | L = 100 | 21.1% | 16.0%—26.0% |
| 16 | L = 20 | 26.4% | 22.4%—30.5% |
| 32 | L = 20 | 23.7% | 19.5%—27.6% |
| 64 | L = 100 | 31.8% | 28.3%—35.3% |

该结果达到原计划中“相同clean下bit降低20%—30%”的强效应量区间，但只适用于85% clean开发工作点，不能外推为所有可靠性目标均降低20%以上。

## 4. 负结果与适用边界

### 4.1 95%和97%目标不可达

四种N下，语义方案的95% clean下置信界均未达到95%或97%，因此不能进行这两个目标的公平节省比较。当前开发证据支持的是85%和90%工作区间，不支持高可靠性工作区间。

### 4.2 在线安装对短会话不利

在L = 20短会话中，在线安装模式通常被初始码本安装和ACK成本抵消：

- N = 8、16、32、64在85%目标下的最佳在线短会话节省均为负；
- N = 16和64虽可达到在线短会话90% clean，但bit仍明显高于精确动作包。

因此不能把预配置码本结果直接表述为“任意部署方式均节省bit”。当前更准确的结论是：

> 任务语义方案适合码本已预配置，或安装成本可在足够长会话中摊销的频谱控制。

### 4.3 冻结风险保护未进入Pareto候选

所有最终候选的更新预留比例均为0。也就是说，冻结的一步风险排序器虽已正确接入，并通过候选集合嵌套测试，但其额外重复保护没有改善本轮matched-clean最优前沿。

这是一个明确的负结果：

- 风险预测模块不能作为当前主要性能贡献；
- 不应因其属于AI模块而强行保留；
- 后续若继续研究预测，应改为多步任务失效风险，并要求其在相同clean下降低系统总bit。

### 4.4 L = 100与L = 500尚未真正区分

2023 pilot的三个评估组均不足100 scenes，因此L = 100与L = 500使用了相同的完整组序列，结果数值相同。这两项不能当作独立重复证据。

2022固定站点数据具有更长序列，下一阶段才可真正验证长会话摊销规律。

## 5. 规模效应

本轮真实协议宽度为：

| N | 紧凑语义更新帧 | 自包含精确动作帧 |
|---:|---:|---:|
| 8 | 42 bit | 56 bit |
| 16 | 42 bit | 59 bit |
| 32 | 42 bit | 62 bit |
| 64 | 42 bit | 65 bit |

随着N增加，精确动作索引宽度上升，而紧凑码字帧保持42 bit。该结构在N = 64的90% clean工作点形成19.7%的显著节省，明显强于N = 8、16、32的约6%—8%，支持“候选信道规模增大时任务码字优势更明显”的研究判断。

但N = 64的增强仍需在2022分组数据和外部活动中复现，当前不能把单个开发pilot趋势写成普遍定律。

## 7. 当前结论

S6.7b粗网格已经补上阶段6最关键的公平性缺口，并给出开发级正证据：

1. 在相同clean约束下，预配置任务语义方案能够显著降低总bit；
2. 85%目标的节省达到约21%—32%；
3. 90%目标在四种N均保持显著正节省；
4. N = 64的规模效应最明显；
5. 在线安装短会话、高于95%的可靠性目标和一步风险保护仍是明确边界或负结果。

因此本阶段可判定为“开发粗网格成功”，但不能判定为“阶段6最终确认成功”。下一道门槛是：

> 在2022 CC1、CC2、LW1的站点×日期分组验证中，冻结候选仍保持matched-clean正节省，并且结论不由单一站点或日期驱动。
