# Phase 2 Spectrum Resource Optimization Report

## 1. 目标定位

本阶段的目标是把前期“频谱语义检测与低开销上报”推进为完整的资源优化闭环：

```text
频谱观测 / 时频图
→ 占用语义提取
→ 低开销语义上报
→ 链路丢包/误码仿真
→ 多 UAV 频谱状态融合
→ 频谱资源块选择
→ 资源选择性能评估
```

因此，本阶段不再只回答“语义包比原始 I/Q 小多少”，而是进一步回答：

> 低开销频谱语义能否在多 UAV 共享频谱压力场景下，帮助系统选择更干净的通信资源？

## 2. 资源优化建模方法

当前使用 RadDet 128 时频图检测结果作为频谱占用语义来源。为了构造低空多 UAV 通信中的频谱资源选择问题，实验将归一化频率轴划分为若干候选子信道。

默认设置为：

- 候选子信道数：4；
- 业务带宽需求：连续 2 个子信道；
- 决策目标：选择真实占用率最低的连续频谱资源块；
- clean resource 判定阈值：所选资源块真实占用率 ≤ 0.02；
- low-interference 判定阈值：所选资源块真实占用率 ≤ 0.10。

每个资源块的占用率由目标框与资源块区域的重叠面积计算得到：

```text
occupancy(resource) =
目标框落入该资源块的面积 / 该资源块总面积
```

系统比较以下方法：

| 方法 | 含义 |
|---|---|
| fixed_ch0 | 总是选择固定资源块 |
| random | 随机选择资源块 |
| semantic_hard | 使用 hard box 语义上报结果选择资源 |
| semantic_hard_rep3 | hard box 语义重复保护 3 次后选择资源 |
| semantic_soft_rep3 | soft 语义重复保护 3 次后选择资源 |
| spectrogram8_gate | 转发 8-bit 频谱图后再检测，链路使用保守门限模型 |
| iq12_gate | 转发 12+12 bit I/Q 后再检测，链路使用保守门限模型 |
| oracle | 使用真实标注占用状态选择资源 |

## 3. 多 UAV 压力场景

单帧 RadDet 目标较稀疏，随机选择资源时也可能较容易选到干净频段。因此，本阶段引入多 UAV 压力建模：

```text
每个决策时刻随机抽取 N 架 UAV 的频谱观测
→ 聚合为一个共享频谱占用地图
→ 各 UAV 独立上报语义/频谱图/IQ
→ 接收端融合收到的信息
→ 选择一个连续频谱资源块
```

这样可以模拟低空场景中多个无人机、多个干扰源或多个局部频谱观测同时存在时的资源竞争压力。

## 4. 代表性结果：4 架 UAV 压力场景

在 `packet_loss=0.2, BER=1e-4` 条件下，4 架 UAV 同时观测并融合时的结果为：

| 方法 | Clean rate | Regret | bits/decision-step |
|---|---:|---:|---:|
| fixed_ch0 | 0.7006 | 0.0150 | 0 |
| random | 0.6962 | 0.0142 | 0 |
| spectrogram8_gate | 0.7020 | 0.0141 | 524288 |
| iq12_gate | 0.6974 | 0.0138 | 96000000 |
| semantic_hard | 0.8846 | 0.0036 | 1045.9 |
| semantic_hard_rep3 | 0.9314 | 0.0012 | 3137.7 |
| semantic_soft_rep3 | 0.9316 | 0.0013 | 3907.3 |
| oracle | 0.9440 | 0 | 0 |

可以看到：

- random / fixed 方法只能达到约 0.70 的 clean rate；
- semantic_hard_rep3 达到约 0.93；
- oracle 为约 0.94；
- 语义重复保护方案已经接近 oracle；
- 语义上报开销仅为约 3.1 kbit/decision-step；
- 相比 12-bit I/Q 转发，语义重复保护仍小约 7649 倍。

这说明当前频谱语义不仅具有压缩意义，而且已经能够支持资源优化决策。

### 5.3 Net utility after switch cost

为了避免资源选择只追求瞬时最干净频段，实验加入了简单的切换成本：

```text
net utility = 1 - selected_resource_occupancy - switch_cost × switch_event
```

当前 `switch_cost = 0.005`。结果如下：

| UAVs | Random | Fixed | Semantic hard | Semantic hard rep3 | Semantic soft rep3 | Oracle |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 0.9918 | 0.9949 | 0.9954 | 0.9965 | 0.9964 | 0.9967 |
| 2 | 0.9870 | 0.9898 | 0.9937 | 0.9952 | 0.9951 | 0.9958 |
| 4 | 0.9778 | 0.9795 | 0.9888 | 0.9915 | 0.9915 | 0.9929 |
| 8 | 0.9587 | 0.9591 | 0.9780 | 0.9808 | 0.9807 | 0.9836 |

加入切换成本后，固定信道在轻负载场景下会因为不切换获得一定优势，但随着 UAV 数量增加，其干扰代价逐渐占主导。语义方法在 4 架和 8 架 UAV 压力场景下仍然具有更高净效用，说明其收益并不只是来自频繁切换，而是来自更准确的频谱状态感知。

趋势非常清楚：

- 当 UAV 数量增加时，频谱占用压力升高；
- random 和 fixed 的 clean rate 快速下降；
- semantic_hard_rep3 始终显著优于 random/fixed；
- 8 架 UAV 时，semantic_hard_rep3 相比 random 的 clean rate 绝对提升约 0.301；
- regret 指标也显示语义方案更接近 oracle。

## 6. 当前可支撑的阶段性结论

本阶段可以支撑如下结论：

1. 频谱语义上报已经形成“检测—传输—融合—资源选择”的闭环；
2. 在多 UAV 频谱压力场景下，语义上报能够明显提升干净资源选择率；
3. 重复保护语义包在丢包和误码环境下仍能保持接近 oracle 的资源选择效果；
4. 相比完整频谱图和 I/Q 转发，语义上报开销低几个数量级；
5. 项目当前更适合定位为“面向低空 UAV 的低开销频谱感知语义上报与资源优化系统”，而不是“调制分类系统”。

## 7. 局限性

当前实验仍有几个需要谨慎表述的限制：

1. RadDet 并非真实 UAV 通信同步采集数据，而是时频目标检测数据；
2. 频率轴和资源块划分仍是归一化建模；
3. spectrogram/IQ 转发基线使用了保守链路门限模型，尚未加入 FEC、ARQ 或部分频谱恢复；
4. 当前频谱语义主要是占用位置语义，类别语义尚不可靠；
5. 多 UAV 压力场景是基于采样叠加构造的仿真压力场景，后续应进一步接入真实多节点或更真实的频谱动态模型。

## 8. 下一步工作

频谱系统后续优先完善：

1. 引入更公平的大载荷基线，例如 FEC、ARQ 或部分频谱图恢复；
2. 增加动态信道切换成本，避免只追求瞬时最优资源块；
3. 增加业务 QoS 指标，例如吞吐、时延、丢包后的任务成功率；
4. 设计多 UAV 融合策略，例如置信度加权、历史频谱地图更新、过期语义惩罚；
5. 在频谱闭环稳定后，接入 UAV 图像语义模块，形成“视觉任务重要性 + 频谱资源状态”的多模态语义传输系统。
